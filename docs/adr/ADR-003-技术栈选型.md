# ADR-003: 技术栈选型（FastAPI + Next.js + SQLAlchemy/SQLite）

- 状态: 已接受
- 日期: 2026-08-27
- 决策者: 龚成

## 背景

ADR-001 定了引擎可插拔，ADR-002 定了 monorepo 与契约先行。
引擎层已锁定 Python + ppt-master（依赖已装、Claude 驱动已跑通），
但前后端技术栈未定。候选：后端 Python/Java/Go，前端 React/Vue。

## 决策

1. 后端选 **Python + FastAPI**：与引擎同语言，复用同一套 `.venv`；
   异步长任务管理成熟（asyncio + 后台任务）；旧项目已验证。
2. 前端选 **Next.js（App Router）+ React + TypeScript + Ant Design**：
   沿用既有脚手架；TS 类型由 openapi.yaml 生成（契约先行）；
   antd 组件全、中文文档友好、适合表单+列表+进度+下载，且利于后续
   agent 修改前端与权限后台页面。
3. 数据库选 **SQLAlchemy + SQLite 起步 → PostgreSQL（后续）**：
   零部署、支持索引/分页；换 PostgreSQL 只改连接串，业务代码几乎不动。
4. 任务记录（历史列表/筛选/分页）存数据库；PPT 产物与草稿文本仍存文件系统。
5. 用户权限为后续功能：任务表预置 user_id，后端预留 JWT 认证与接口级权限，
   前端用 NextAuth/自管 token。起步阶段不实现登录。
6. 引擎驱动 agent 可在 claude / codex / hermes 间切换（契约 `agent` 字段）。

## 后果

- 正面：全栈语言少（Python + TS），单语言维护成本低；契约驱动前后端并行；
  数据库迁移路径清晰（SQLite → PostgreSQL），技术债最小；权限可平滑扩展。
- 代价：FastAPI 生态较 Node 轻量，极大型团队生态不如 Spring；SQLite 不适合
  高并发多实例，达到该阶段前需迁 PostgreSQL（计划内）。
