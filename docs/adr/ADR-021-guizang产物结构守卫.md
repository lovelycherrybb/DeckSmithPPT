# ADR-021: guizang 产物结构守卫——存在不等于能用，可自愈就地修，修不了如实判失败

- 状态: 已接受（已实现并验证）
- 日期: 2026-09-28
- 决策者: 龚成
- 相关: ADR-011（guizang 运行时归位 Claude 技能）、ADR-012（交付形态与引擎运行时数据布局，
  决策 1 的产物落点契约）、ADR-016（token 消耗口径）、ADR-018（分层枚举）、ADR-019（调度循环）；
  设计稿 `docs/research/2026-09-28-引擎产物结构守卫.md`

## 背景

### 一、事故形态：一份"自检全过"的废稿

任务 `c7f3edd4`（2026-09-28，guizang_ppt 引擎）产物 133,600 字节、12 页齐全、`</html>`
收尾完整、技能自带校验脚本报 0 errors、任务状态 completed——但**打开后停在封面，
键盘 / 滚轮 / 圆点全部失效，`?slide=N` 也无效**。

根因：产物里根本没有 `<div id="nav"></div>`。导航脚本 `const nav=document.getElementById('nav')`
取到 null，紧接着 `nav.appendChild(b)` 抛 `TypeError`，整段脚本死在 `go()` 与
`keydown` 监听注册之前。反向验证：只把这一行补回去，`?slide=5` 立刻跳到第 5 页、
12 个圆点生成、`transform=translateX(-400vw)`。

### 二、为什么会被删掉：注入越界

上游模板的不变量（实测两份模板同构）：

| 元素 | magazine | swiss | 与注入区关系 |
|---|---|---|---|
| `<!-- SLIDES_HERE -->` | :537 | :1337 区 | **在 `#deck` 内部**，是授权填充区 |
| `<div id="nav"></div>` | :541 | :1341 | **在 `#deck` 闭合之后**，不属填充区 |
| `<!-- 演讲备注` | :543 | :1343 | 紧随 `#nav`，两模板均唯一出现 1 次 |

agent 按 prompt 的"分批 Edit"协议注入 12 页时，最后一批的替换片段越过了 `#deck`
闭合线，把 `#nav` 一起替换掉了。

### 三、这是概率性失手，不是确定性 bug

历史 8 份真实 guizang 产物中 **7 份骨架完好、1 份丢 `#nav`（≈12.5%）**。同一模板、
同一流程、跑出不同结果——LLM 多轮 Edit 的锚点选择本身带随机性。因此**不可能靠
"把 prompt 写得更严"根除**，只能靠机制兜底。

### 四、两个现存的放行缺口

1. **引擎侧**：`_artifact_ready` 只判"文件存在 + ≥2048B + mtime 晚于启动"。133KB 的
   坏产物与 133KB 的好产物在这一关完全等价。
2. **技能侧**：`validate-presenter-mode.mjs` 只校验演讲备注与 `data-slide-id` 对齐，
   不校验骨架完整性与可导航性。

上游 `lib/guizang-ppt-skill/` 是 git submodule，按 AGENTS 规则 4 属只读区——
**兜底只能加在 DeckSmith 侧**。

## 决策

### 决策 1：守卫挂在 `status()` 的 completed 分支，一处覆盖两条路径

`GuizangPptEngine.status()` 是全引擎**唯一**把"文件存在"翻译成"任务成功"的地方。
`_supervise` 在产物就绪时只释放租约、把终态交给 `status()`，所以只挂这一处就同时
覆盖 supervisor 存活与已死两条路径，不需要第二道检查。

判据（R1–R4，全部为确定性字符串 / 解析断言）：

| # | 校验项 | 判据 | 可自愈 |
|---|---|---|---|
| R1 | 文件完整 | 含 `</html>` | 否 |
| R2 | 页数 ≥1 | 复用 `scan_slides()` 的**已闭合**页计数非空 | 否 |
| R3 | 注入残留 | 不含 `SLIDES_HERE` | 否 |
| R4 | 骨架三件套 | `id="deck"` / `"nav"` / `"hint"` **各恰 1 次** | 仅"缺 nav" |

页计数刻意复用 `scan_slides()` 而不是另写一套：否则会出现"守卫说 4 页、页墙显示
3 格"这种两套逻辑的边界差（与 ADR-012 决策 1 的单一事实源口径一致）。

**刻意不校验**：内容质量、版式美观、SPEAKER_NOTES 对齐（上游脚本已管且不致命）、
页数是否等于请求页数（篇幅本就授权 agent 判断）。守卫只管"结构上能不能用"。

### 决策 2：三档分流——自愈 / 判失败 / 不重跑

**可自愈只认一种组合**：全部缺陷恰好是"缺 `#nav`"一条，且 `#deck`、`#hint` 均完好、
锚点 `<!-- 演讲备注` 唯一存在。修复内容与模板原文一字不差，插在锚点前（即模板
原始位置）。修完**必须重跑全量校验**，通过才采用。

不扩大自愈范围的三条理由：多种缺陷并存说明破坏面更大，补一个 nav 只是掩盖问题；
锚点缺失时硬插等于猜位置；只认已实测复现的形态，不发明未验证的修复。

**不可自愈 → 如实判 failed**：`error` 写"产物结构不完整，无法正常使用：<逐项事实>"，
run.log 留一行 `🛑 结构守卫拦截`，job.json 记 `guard.defects`。拦截**不偷改产物**——
文件原样保留，供复盘与页墙查证。

**一律不自动重跑**。本次任务实测消耗 **3,777,928 tokens**；自动重跑等于"失手必
双倍烧钱"，且重跑掷的是同一个概率骰子（p → p² 的改善不划算）。失败任务走既有
retry 入口（`RETRYABLE_STATUSES` 已含 failed），重跑与否由人决定。已烧的
`token_usage` 不因判失败而隐瞒（ADR-016 口径）。

### 决策 3：失败语义走现成链路，不动调度器与契约

引擎把原因写进 job.json 的 `error`，调度器 `_finalize` 本就会把它抄进 DB 的 error 列
（scheduler.py:327-328）——**零改动贯通到界面**。因此：

- **不改契约**：状态枚举、字段、端点全不变，`error` 本就是自由文本；
- **不改协议**：不做成 `PptEngine` 钩子。做成钩子要契约描述 +
  `registry._derive_capabilities` + 前端消费三处同步，而守卫是引擎内部质量责任，
  调用方无需感知。ppt_master 将来要加 pptx 守卫，在自己 impl 里照抄模式即可；
- **不做成系统设置开关**：守卫只在 agent 失手时触发，正常路径零感知；做成开关
  等于给静默坏产物留后门。

### 决策 4：文案口径——任务语义打头，技术事实在括号里

界面展示的是"产物结构不完整，无法正常使用：缺少翻页导航容器（id=\"nav\" 被注入
过程误删，页面无法翻页）"这种形态。沿用 ADR-020 与"报错说人话"的既有口径，
后端文案与界面用词一套，不得两套说法。

## 后果

**正面**

1. 骨架级坏产物不再以 completed 出厂；静默失败变成显式失败或显式自愈。
2. 已知失手形态（本次案例）零成本修复，不打扰用户、不烧额度。
3. 每次拦截 / 自愈都在 run.log 与 job.json 留痕，可审计可回溯。
4. 守卫是纯函数（`guard.py` 不碰文件、不起进程），可脱离引擎单测。

**代价与边界**

1. 守卫只保"能不能翻"，不保"内容对不对"。版式错乱、文字空洞仍需人工或后续校验。
2. 自愈范围刻意窄到"只缺 nav"一种组合。其它骨架损伤一律判失败——这是有意的保守，
   宁可让用户重跑一次，也不静默产出一份"被代码改过、来源不纯"的产物。
3. 判 failed 后产物文件仍在，页墙仍可看（证据视图）。任务态是 failed，不构成分数冒领。
4. 概率性失手仍会发生，守卫只是让它**可见**。要真正降频，需上游技能把
   "严禁触碰 SLIDES_HERE 之外骨架"写成硬约束（属只读区，须走上游，不在本 ADR 范围）。

## 验证

- `packages/engine/tests/test_guizang_guard.py` 18 条：纯函数 12 条（R1–R4 各项、
  自愈边界、幂等、文案形态）+ 引擎集成 5 条（completed / 自愈留痕 / 拦截不偷改 /
  非 UTF-8 不崩 / 终态短路不重入）+ **真实案例回归锚 1 条**（对 `c7f3edd4` 实际产物
  跑守卫，自愈成功且 12 页不变；产物不随仓库分发时自动 skip）。
- 全量回归：engine 54、backend 116、contract 34 全过，`check-alignment` 通过。
- 既有 `test_guizang_engine.py` 4 条用例的假产物夹具升级为"结构合法"最小产物。
  这些用例测状态机 / 续跑 / 计量，不是产物结构；旧夹具那种 `<div class="slide">`
  拼出来的假 HTML 在真实世界根本翻不动，**守卫拦下它是正确的**，故升级夹具而非
  放松判据。
