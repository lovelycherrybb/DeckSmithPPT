# ADR-025 · 逐页拖拽编辑器"直接操作"选型：自研覆盖层（不用 canvas 编辑库）

- 状态：已接受
- 日期：2026-10-06
- 关联：ADR-023（逐页修改/子演示文件与任务契约）、ADR-014/015（上游只读、双引擎）；设计细节见 `docs/research/2026-10-06-拖拽编辑器直接操作-覆盖层方案调研.md`

## 背景

`MultiPageSvgEditor`（"拖拽编辑"）现仅支持点选 + 移动 + 底部属性栏改字/色/字号/删除。需求升级为：选中元素后在画布上**就地缩放、旋转、改字、调样式**。业界确有成熟编辑组件（Fabric.js / Konva.js / svg-edit 等），需决定是否引入。

## 决策

**采用"自研覆盖层 + 直接编辑真实 SVG DOM"（路线 A），不引入 canvas 编辑库。**

- 编辑对象始终是每页那份真实 SVG DOM；新增一层**独立的、React 渲染的覆盖层 `<svg>`**（与页面同 `viewBox`、绝对定位叠加）承载选择框、缩放手柄、旋转手柄、浮动样式条。
- 坐标换算用 `svg.getScreenCTM().inverse()` 精确映射到用户坐标。
- 缩放按元素类型分流：文字改 `font-size`、`rect/image` 改 `width/height`、`circle/ellipse` 改 `r/rx,ry`、`path/g` 用 `transform` 加 `scale()`；旋转用 `transform` 加 `rotate(deg cx cy)`。
- 所有写操作沿用既定铁律：**不跨帧持有节点引用**，按"页号 + 结构路径"每帧从实时 DOM 重新解析目标，改完 `commitPage` 序列化回 html + 草稿。

## 理由（为什么不选 canvas 库）

本项目事实来源是"真实 SVG + 上游 `finalize→quality→svg_to_pptx` 确定性重导出"（ADR-014/015/023）。Fabric/Konva/svg-edit **接管渲染并自序列化 SVG**，会丢失或改写我们依赖的保真结构（渐变、`<tspan>` 多行排版、`data-pptx-*` 属性、SMIL、既有 transform 组合），与"编辑原 SVG→原脚本重导出"契约直接冲突。路线 B（interact.js 只做手势数学、渲染仍自研）作为备选，仅当自写手势数学成本过高时再引入，以免多背一个依赖。

## 后果

- 正面：保真与重导出链路不被破坏；交互层与编辑层职责清晰；与刚修复的"重渲染替换子树"约束天然契合。
- 代价：缩放手柄、旋转、就地改字、坐标换算等手势逻辑需自研自测；代码量中等。
- 必须验证：`scale/rotate/改字` 写法能被 `svg_to_pptx` 正确读回（尤其描边宽度是否随 scale 变形），每步 `tsc` + 真浏览器复验 + 一次免费确定性重导出抽检。
- 范围：纯前端，**不改后端契约 / openapi / 引擎能力**（产出仍是编辑后的逐页 SVG 内容）。

## 分期

P1 选择框+缩放+就地改字+删除/复制；P2 旋转+浮动样式条；P3 多选成组/吸附对齐/撤销重做/键盘微调。
