# ADR-026 · 四盏"永远绿的灯"改成真检查：漂移比路由、契约比响应、e2e 跑闭环

- 状态：已接受（已实现并验证会红）
- 日期：2026-10-07
- 关联：ADR-018（状态分层枚举）、ADR-019（调度循环与两个注入点）、ADR-024（并发闸口径）、ADR-012（交付形态与运行时布局）；触发本次改动的问题清单见 `outputs/decksmith-从构建到交付-科普.html` 第五节

## 背景

给项目做"从构建到交付"科普时逐条核对 CI，发现流水线上有四盏灯**只会打印成功、不会失败**，
而它们的命名恰好都在承诺一件没做的事：

1. `.github/workflows/ci-frontend.yml` —— 全部内容是
   `echo "技术栈未定，选型后补充前端 CI"`。但技术栈早在 ADR-003（2026-08-27）就定了
   Next.js 15 + React 19 + TypeScript + Ant Design，前端有 `tsconfig.json` 与 348K 源码。
   **注释与现实脱节，绿灯与实际脱节。**
2. `.github/workflows/ci-e2e.yml` —— `echo "全栈选型后补充 e2e 测试"`，而 `tests/e2e/`
   只有一个 `.gitkeep`。于是"一次提交能不能真的跑出一份 PPT"从未被任何一层机器验证过：
   单测层强制 stub 且不碰调度器，契约层只看形状，中间那段（落库 → 调度线程认领 →
   `engine.submit` → 轮询 → `_finalize` → 登记演示文件）只靠人工真跑目视。
3. `scripts/check-drift.sh` —— 五行脚本，正文是一句
   `echo "TODO: 实现契约漂移检查（契约 hash 与生成产物 hash 比对）"`，恒返回成功。
   它挂在契约流水线第一步，名字叫"检查契约漂移"，**什么也没查**。
4. `tests/contract/api_contract_test.py` —— 12 行，只断言 `openapi.yaml` 文件存在，
   自己写着 `TODO: 选型后接入 schema 校验`。同目录另外三个契约测试是真在做事的
   （`engine_contract_test.py` 307 行、`job_status_set_test.py` 83 行、
   `cancel_capability_test.py` 55 行），所以这一盏最隐蔽：文件名叫"API 契约测试"，
   看 CI 的人会以为响应形状有人守着。

这三处（前两处 + 第四处）违反的正是 `scripts/test.sh` 顶部注释里本项目自己写下的教训：
旧版 `pytest ... || true` 让契约测试挂了也一路绿，"等于装了一盏永远亮的灯"；
旧版缺 pytest 时打印"跳过"再正常退出，结果"本地和云端连续几周显示全绿，
而实际一个用例都没跑过"。

## 决策

### 1. `check-drift` 查"接口集合漂移"，两个方向都查

新文件 `scripts/check-drift.py` 承载逻辑，`check-drift.sh` 退化为薄入口
（与 `generate-types.sh` + `gen-engine-types.py` 同一分工，CI 侧命令不变）。

比的是 **`docs/contracts/openapi.yaml`（人写的契约）** 与
**`app.openapi()`（后端代码自述的契约）** 的 `(path, method)` 集合：

- 契约有、代码无 → 前端按契约打过去就是 404，契约在说谎；
- 代码有、契约无 → 接口裸奔，不参与类型生成与对齐校验。

三条口径写死并体现在输出里：**路径参数只比形状**（`{job_id}` 与 `{id}` 视为同一路径，
参数名不进 URL 模式，不构成接口漂移）；**只比 `/api/` 前缀**（FastAPI 自带的
`/docs`、`/openapi.json` 不属对外契约）；**方法用白名单**（首版用黑名单漏掉了
`operationId` / `responses`，把契约里一处缩进错误读成了两个"幽灵接口"）。

**取不到数据即失败**：契约解析不了、后端 import 不了、任一侧集合为空，一律 `exit 1`。
绝不允许"没比上也算过"——这条是本次改动的立身之本。

不查字段级 schema 差异，避免与 `check-alignment.py`（vc_design ↔ contracts）和
`api_contract_test.py`（真实响应 ↔ 契约）重复。

### 2. `api_contract_test` 用 `jsonschema` 校验真实响应，不引入 schemathesis

`schemathesis` 是属性级 fuzz（随机入参打接口），价值在探边界，但失败面太宽、
红得不稳定，一旦被视为 flaky 就又被忽略——那正是本次要消灭的病症。这里要守的
是更窄的一件事：**出参形状与契约一致**。用 `jsonschema` 直接校验真实响应，
零随机性、可复现。

校验强度取 `additionalProperties: false`，且**递归作用到 `components` 里所有带
`properties` 的对象**。两点理由：FastAPI 的 `response_model` 会把输出裁剪到 pydantic
字段集，所以"后端多吐字段"物理上不会发生，关门真正能抓的是"契约声明了而模型没有"；
而 `type: object` 且无 `properties` 在 OpenAPI 里表示自由对象（本契约的
`EngineInfo.params_schema` 装的是一整份 JSON Schema），对它也关门会造成假红，故排除。

用例表只挑**无需入参、无需既有数据**的读接口（`/api/version`、`/api/engines`、
`/api/settings/capacity`、`/api/auth/me`、`/api/projects`、`/api/jobs`）——这类接口的
响应完全由代码决定，校验它才是"契约 vs 实现"，而不是"测试数据 vs 测试数据"。
另设 `assert checked >= 5`，防止将来接口被改名导致"一条都没校验但测试通过"。

**`nullable` 归一化**：契约头写 `openapi: 3.1.0`，正文却有 18 处 3.0 语法的
`nullable: true`。`jsonschema` 不认识 `nullable`，会当未知关键字忽略，于是"可为 null"
的字段一旦真返回 null 就被判违规——**假红**。测试侧先归一化为 `type: [T, "null"]`，
同时新增一条"只准减少不准增加"的上限断言（`found <= 18`），把这笔债登记在机器上，
而不是只写在注释里。一次性改完 18 处契约写法不在本批范围内。

### 3. CI Frontend 跑 `npm ci` → 生成类型 → `tsc --noEmit` → `next build`

Node 钉 20，与交付镜像 `node:20-slim` 同大版本——理由与 `ci-backend.yml` 钉
Python 3.11 完全同一条：用更新版本跑绿而镜像用旧版本等于没验（本机 node 已是 25）。

生成类型之后加一道**断言生成物真的产出了**：两个 `.d.ts` 非空，且
`grep -q '"/api/jobs"' api.d.ts`。否则生成器哪天空转，这条流水线就悄悄退化成
"构建了一个用的是陈旧类型的前端"。

触发面补上 `docs/contracts/**`、`packages/shared/**`、`scripts/generate-types.sh`、
`scripts/gen-engine-types.py`——类型是从契约生成的，契约改了必须重跑。

### 4. CI E2E 跑最小真闭环，走 lifespan 的调度线程而不是手调 `sweep()`

`tests/conftest.py` 在**模块导入期**把 `DATABASE_URL` / `DECKSMITH_JOBS_ROOT` /
`DECKSMITH_FORCE_STUB=1` / `DECKSMITH_SCHEDULER_INTERVAL=1` 钉进环境变量。
必须在这里做、且必须早于任何 app 模块导入：`app/core/db.py` 在导入期就绑定了
模块级 `ENGINE` / `SessionLocal` / `JOBS_ROOT`，事后 monkeypatch 只能补一部分调用点，
剩下那部分仍指向开发库 `outputs/decksmith.db`——ADR-019 给调度器留两个注入点，
注释里明令禁止的就是这个后果。

用 `with TestClient(app)` 进 lifespan，让**生产同一套装配**跑起来（建表 → 播种管理员
→ 起调度线程），测试侧只发 HTTP。手调一拍 `sweep()` 只能证明函数能跑，证明不了
那条线程真的起来了、也证明不了关停顺序是对的。

三条用例：草稿任务闭环（含"恰好落 1 份草稿实体"从而覆盖终态副作用不重复）、
输出任务闭环（`.pptx` 落盘 → 登记演示文件 → 下载接口取回并校验 zip 魔数与体积）、
归属隔离（换一个 TestClient 会话 = 另一份访客 Cookie，看不到前一条的任务）。

`_submit` 里断言"受理即 `queued`"，守的是 ADR-019 决策 2 那条口径：一旦有人把
fork 搬回请求线程，这里当场红。

### 5. CI Contract 的安装清单改为走单一入口，并把装依赖排到漂移检查之前

漂移检查现在要 `import app.main`，`fastapi` / `sqlalchemy` / `pydantic` 缺一个它就
取不到数据（而它取不到数据时是 `exit 1`）。原先那行手抄的
`pip install pytest python-pptx==1.0.2 pyyaml` 既不够、又是"两处维护同一份依赖认知"
的重复知识源，改为 `pip install -r packages/backend/requirements.txt` 再补测试专用包。
`ci-e2e.yml` 同口径。

漂移检查的触发面补 `packages/backend/**`：只盯 `docs/contracts/**` 的话，
"加接口忘写契约"这个方向永远不会被触发。

## 后果

**1. 四盏灯都验证过"能红"**，各注入一次真实破坏：

| 灯 | 破坏方式 | 结果 |
|---|---|---|
| check-drift | 契约里加一个后端没有的 `GET /api/zzz-mutation-probe` | `❌ 契约有、后端没有` + `exit 1` |
| check-drift | `DATABASE_URL` 传非法串，导致取不到路由表 | `无法完成比对` + `exit 1`（不是"没比上也算过"） |
| api_contract | 给 `VersionOut` 加一个必填的 `zzz_mutation_probe` | `GET /api/version：$ 'zzz_mutation_probe' is a required property` |
| api_contract | 响应多吐一个契约里没有的字段 | `Additional properties are not allowed` |
| CI Frontend | 在 `src/lib/jobStatus.ts` 里把 string 赋给 number | `error TS2322`（在隔离副本里验，未污染在跑的 dev 服务） |
| CI E2E | 把 `_finalize` 里的 `persist_presentation` 跳过 | `期望登记 1 个演示文件，实得 0` |

本地全绿基线：contract 39 passed、e2e 3 passed（6.8s）、`check-drift` 46 ↔ 46 一致、
`tsc --noEmit` 无输出、`next build` 成功产出 5 条路由。

**2. 改动当场抓到两个真实缺陷**（这才是"灯亮了有用"的证据）：

- **契约缩进错误**：`/api/agent/sessions/{session_id}` 与 `.../stream` 两个 path item
  的操作直接挂在 path 下、缺 `get:` 键（内容多缩了两格造成的）。后果是
  `openapi-typescript` 不给这两个接口生成类型，前端调它们是无类型的。已补 `get:`。
- **契约说谎**：`CurrentUser.user` 写的是 `$ref: User` + 注释"未登录时缺省（不存在）"，
  而后端 `response_model` 是 `UserOut | None`，序列化出来**恒为 `"user": null`**。
  前端按生成的类型判"字段不存在"就会判错。已改为 3.1 合法形态
  `oneOf: [{$ref: User}, {type: 'null'}]`（`$ref` 旁写 `nullable` 在 3.0 语义下无效）。

**3. 测试解释器新增两个包**：`httpx`（TestClient 的运行前提）、`jsonschema`
（响应形状校验）。已写入 `packages/backend/requirements-dev.txt` 并同步三条流水线的
安装清单。注意 `requirements-dev.txt` 顶部那段"本机 `.venv` 没有 pytest、测试实际用
系统 python3 跑"的如实记录**仍然成立**，本次没有顺手解决它——那是 ADR-012 决策 8
"单一解释器"在本机的残留缺口，与 CI 无关（CI 里两边都是 3.11）。

**4. 顺带暴露：单元测试层存在闪断，本批未修。** 五连跑中 1 次失败，且失败用例不固定
（`test_draft_async.py::test_草稿提取抛异常置failed` 与
`test_guizang_engine.py::test_无产物则判失败` 都出现过），症状是后台线程与轮询
deadlines 的竞态——失败时 `error` 字段被"claude 子进程结束但未找到产物"覆盖，
说明引擎侧有两条路径在抢同一行。**一条会随机红的灯，与一条永远绿的灯同样有害**：
前者训练人重跑并忽略，后者训练人信任不存在的东西。已登记进 README「尚未完成」，
按本 ADR 的口径应当下一步处理：把这两条用例的等待改成事件驱动而非轮询 + 超时。

**5. 覆盖面如实说明**：e2e 只有"提交 → 调度 → 出片 → 下载"这一条最小闭环，
撤销、超时、逐页修改、多身份并发尚未端到端覆盖；`packages/frontend/tests/` 仍为空，
`npm test` 仍是 TODO，CI Frontend 跑的是类型检查与构建、**不含组件测试**。
本 ADR 只承诺"四盏假灯变成真灯"，不承诺测试覆盖率达标。
