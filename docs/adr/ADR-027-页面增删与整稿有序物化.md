# ADR-027: 页面增删与整稿有序物化——结构改动不花 AI，内容仍走单页通道

- 状态: 已接受（契约已落，代码随层三实现）
- 日期: 2026-10-09
- 决策者: 龚成
- 相关: ADR-023（逐页修改与草稿载体模型——本 ADR 补上"页数可变"这块）、ADR-024（改稿走快通道）、
  ADR-025（拖拽编辑器）；`docs/contracts/openapi.yaml` 的 `ReviseRequest.deck`、`DeckPageSpec`

## 背景

对话式改稿（ADR-023）只作用于"当前页"，页数与页序是冻结的。真实使用立刻提出：

- 「在第 1、2 页之间加一页目录」→ 需要**插入**新页；
- 「删掉第 5 页」→ 需要**删除**。

最初设想了"整稿对话改版"：一次 AI 调用吃下全部页 + 指令，返回稀疏 deck spec（含插页/
删页/合页/调序与跨页改样式）。评审时用户把它砍到了本质——

> 其实只要给我页面的增删功能就行了，其他的我进入单独页面去改。比如加目录：新增一页，
> 然后在这一页告诉 AI 帮我加目录，不就行了？

这个简化成立：单页对话改稿已经能"在指定页生成任意内容"，缺的只是**把页本身加进/移出
这份稿子**的能力。整稿 AI 协议（贵、慢、未动页有被转写的风险）属于过度设计，砍掉。

## 决策

### 决策 1：增删在前端草稿里完成，提交走有序 deck 清单

前端草稿从 `Record<index, content>`（按页覆盖）升级为**有序页清单**：每项要么引用源页
（`ref`，可带替换内容），要么是新增页（`name` + `content` 整页 SVG）；不在清单里的源页
即被删除；数组顺序即新页序。「整体另存」提交 `ReviseRequest{deck}`。契约里 `deck` 与
`pages` 同给时以 `deck` 为准。

### 决策 2：结构落地归引擎确定性物化（0 token、秒级），不碰 AI

`revise()` 新增 `deck` 入参：在工作副本 svg_output 里按最终顺序重写页文件——

- 源页沿用原文件名语义（去掉旧编号前缀），新增页按语义名落 `NN_<name>.svg`；
- 全部文件按新序统一重编号，被删除的源页文件移除；
- 随后走既有 `_deterministic_export`（finalize_svg → quality_checker → svg_to_pptx），
  质量闸照常把关、失败原因透出。

校验前置：ref 合法且不重复、新增页 content 非空（空页教训）、清单至少剩一页；非法直接
判任务失败并给原因。

### 决策 3：新增页从空白模板起步，内容由用户在单页通道自行补全

前端"新增页"插入一张最小合法空白页（1280×720、白底、符合页文件约束的 SVG 骨架），
并自动把当前页切过去；用户随后用「对话式改稿」（"帮我加目录"）或拖拽编辑器/源码编辑
填内容。AI 不做任何结构判断，也就没有整稿调用的成本与风险。

### 决策 4：明确不做（v1 边界）

- ~~整稿 AI 协议（revise_deck）~~：已从契约移除；
- 合页/调序/跨页批量改样式：数据模型（有序清单）天然支持调序与合页的扩展，但 v1 不做
  UI、引擎不特判；需要时按 ADR 补充。

## 后果

1. 页数与页序成为草稿的一部分：预览列表、拖拽编辑器、逐页对话改稿都以有序清单为准渲染；
   新增页没有服务端 URL，预览与编辑一律走草稿内容。
2. 增删与重导出全程 0 token、秒级；唯一花 AI 的地方仍是单页对话改稿（用户自主发起）。
3. 空白页若未经加工直接另存，会以"占位骨架"进入成品——属用户显式选择，质量闸只拦硬伤
   不拦留白。
4. 引擎协议 `PptEngine.revise` 增加可选 kwargs `deck`，向后兼容；不实现物化的引擎收到
   `deck` 时应明确报"不支持"，而非静默降级。

## 层三实现点

- 契约：`DeckPageSpec`（ref/name/content）/ `ReviseRequest.deck`（已落，类型已再生成；
  `revise_deck` 已按本决策移除）。
- `packages/engine/core/protocol.py`：`revise(..., deck: list[dict] | None = None)`。
- `packages/engine/impl/ppt_master_v6/engine.py`：`_materialize_deck`（重编号、删文件、
  写新页）+ `revise()` deck 分支（优先级 `deck > pages`）。
- 后端：`ReviseRequest` schema 增加 `deck`，提交处透传 `engine.revise(deck=...)`。
- 前端 `RevisionWorkbench.tsx`：预览列表加「新增页/删除页」，草稿升级有序清单，新增页
  标注，另存统一走 `deck`。
