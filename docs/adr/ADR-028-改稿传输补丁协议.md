# ADR-028: 改稿传输改用补丁协议——AI 只回修改块，后端应用后仍回传整页

- 状态: 已接受（已实现并验证）
- 日期: 2026-10-09
- 决策者: 龚成
- 相关: ADR-023（逐页修改）、ADR-027（页面增删）；`packages/backend/src/app/agents/page_revise.py`；
  对外契约不变（`AgentExecuteRequest.kind=revise_pages` 的出入参形状与 openapi 描述继续成立）

## 背景

对话式改稿旧协议要求 AI 把改后的**整页 SVG** 逐字重发。实测：第 5 页 4.2KB ≈ 1.5~2K 输出
token，定向小改（改色/改字号）也要 100s+；一次"科技风一点炫酷一点"的整页改版跑到 4 分半
仍在生成。输出 token 是纯瓶颈，输入（页源码）预填很快，不是问题。

## 决策

### 决策 1：AI 默认只回 `{search, replace}` 补丁，本地精确匹配应用

提示词改为：每页回 `{"index":n,"patches":[{"search":"页内逐字原文","replace":"新文本",
"replace_all":false}]}`；`search` 必须从页源码逐字复制（含空格引号换行）、取页内唯一的
一小段连续原文；一处修改一个补丁、按序应用。

实测（4.2KB 的第 5 页，"把大标题改成蓝色"）：AI 输出从整页 4.2KB 降到 **261 字符 1 个补丁**，
端到端 ~50s（旧协议同类指令 100s+ 起步、重排版指令直接 300s 撞超时线）。剩余耗时主要是
模型对整页的**思考时间**（`claude -p` 冷启动基线仅 3.5s，输出已不是瓶颈）——再往下压要么换
更快的模型档位，要么用流式进度改善体感，均不在本 ADR 范围。

### 决策 2：大改版兜底——过半重写允许直接回 `content` 整页

"整页换风格"这类指令补丁块多、收益打折，AI 可自行判断直接回整页内容；两种形态可在同一
数组里混用。补丁失配（search 找不到）不静默吞掉：整轮判失败并把"第 X 页第 Y 处没匹配上
（search 开头「…」）"回给用户，重发指令即可。

### 决策 3：补丁只活在"AI ↔ 后端"内部，对外协议零变化

后端应用补丁得到整页内容，仍按 `[{index, name, content}]` 回给前端并入草稿——前端、契约、
`pages` 手动通道、整体另存链路全部不动。补丁解析/应用在 `page_revise.py`，配回归测试
（应用正确性、只换第一处 vs replace_all、失配/越界/重复/空内容全抛错）。

## 后果

1. 定向改稿的输出量降一个数量级，不再可能因"整页重发"撑爆 300s 超时线；端到端 ~50s，
   其中模型思考占大头（后续提速方向见决策 1 实测段）。
2. 失配错误可归因（哪页哪处、search 开头是什么），用户能自己把指令说得更具体后重试；
   不做自动重发兜底（避免隐性二次计费）。
3. 输出 JSON 变小也顺带降低了历史上"大 JSON 输出偶发异常"面的暴露。
