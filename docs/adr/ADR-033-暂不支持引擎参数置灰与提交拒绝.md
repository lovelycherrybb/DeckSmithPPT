# ADR-033: 暂不支持的引擎参数——界面置灰并写明原因，提交期一律拒绝

- 状态：已采纳（决策 6 待龚成确认解除条件）
- 日期：2026-11-02
- 相关：ADR-031（v6 参数面扩张）、ADR-032 决策 5（缺键标红，不让人"以为生效了"）、AGENTS.md 规则 9（禁止假控件）、规则 10（参数必须支持不选）

## 背景

2026-11-02 做了一轮引擎外部依赖盘点（详见 `docs/research/2026-11-02-引擎外部依赖盘点.md`），实测结论是：`ppt_master_v6` 参数面里有两项在**当前部署里兑现不了**，但界面上照常可选，VIP 和管理员选了会拿到"任务成功、结果里没有这项"的产物。这正是规则 9 禁止的假控件，只是断点不在代码里，在镜像依赖和运行配置里。

凭据（当日均为实测，非推断）：

1. **旁白音频 `narration_audio`**：配音库在镜像里可用（`decksmith/app:0.6.4` 内 `edge_tts` 导入成功，版本 7.3.1），但"把音频嵌进 PPT、按音频时长定时翻页"要读每段音频的真实长度，靠的是 ffmpeg 系列工具——同一个镜像里实测两个命令都 MISSING（`which ffmpeg` / `which ffprobe` 均无输出）。后端镜像的 apt 安装清单里没有它（`packages/backend/Dockerfile:72` 起那一段），启动脚本也不补装（`deploy/entrypoint.sh` 内无 install 字样）。上游把这条写成硬前置（`lib/ppt-master-v6/skills/ppt-master/scripts/docs/narration.md:7`）。
2. **AI 生图 `image_usage` 取值 `ai`**：生图脚本要求显式指定后端，未配置时打印"No image backend configured for Path A"后退出（`lib/ppt-master-v6/skills/ppt-master/scripts/image_gen.py:409-437`）。当前生产 `.env` 实测只有 8 项模型接入相关的键，无任何生图键；交付模板 `deploy/.env.example` 通篇也没有生图项的样例。

同批盘点还确认了两项"半通"（网络搜图、允许上网补素材：不需密钥但需容器出公网，开发机容器实测部分域名连不通）与一项结构性做不到（配音再导成 MP4 需 Windows 版 PowerPoint）。这些**本批不动**，理由见决策 4。

## 决策

### 决策 1：置灰由契约字段驱动，不在前端按参数名硬编码

契约新增两个可选标记，都只承载"这项现在不能用"这一件事：

- `x-unavailable`（字符串）：标在参数上，值给人看的中文原因。整项不可用。
- `x-unavailable-values`（对象：取值 → 中文原因）：标在参数上，只禁其中几个取值，其余照常可选。

前端一律读契约字段决定置灰，绝不写 `key === 'narration_audio'` 这类判断。原因：本仓已定口径"前端不硬编码引擎参数、照 schema 动态渲染，改契约即改界面"，写死名字等于把这条规矩开个常例。

### 决策 2：不复用 `x-hidden`

`x-hidden` 的语义是"纯工程旋钮，压根不给用户看"（`DraftsPanel.tsx:491`）。今天要的是相反的形状：**让用户看得见这功能存在，但明确知道现在选不了**。隐藏会让用户以为系统没有这个能力，也会在以后放开时让人怀疑是不是一直有、只是被藏了。所以另起字段，不改 `x-hidden` 的含义。

### 决策 3：提交期一律拒绝，不许静默丢弃

后端在提交期独立复核，命中暂不支持项即返回明确错误，含 VIP 与管理员。

**「选了不用」不算踩到**：判据是"值确实要求启用"才拒——假值、空值、空列表一律放行。旁白音频选「关闭」是用户真实的取舍，不做配音本来就做得到，拦它等于连"明确不要"都不许表达。规则 10 的布尔例外讲的是同一条道理。

为什么不能像"普通用户不可选"那样直接清空（现状：非 vip 时 `engine_params = {}`，`packages/backend/src/app/service/jobs.py:250-254`）：那里的"清空"是权限裁剪，用户本来就无权表达该意愿；而这里是**用户明确表达了要，系统悄悄不做**，正是"以为生效了"。与 ADR-032 决策 5 同一口径——宁可当场报错，不事后含糊。

界面已置灰、后端仍要拒绝：置灰只挡得住从界面点的人，挡不住直接调接口的请求。这条由本 ADR 决策 5 的检查看守。

### 决策 4：本批只处理"确定兑现不了"的两项，半通项不动

判据写死在此，不许到期改口：**只有"缺依赖或缺配置，流程必失败"才标暂不支持**。据此：

- 标：`narration_audio`（缺 ffmpeg 工具）、`image_usage` 的 `ai`（缺生图后端配置）。
- 不标：`web` 网络搜图、`allow_web_research` 上网补素材——这两项**零密钥也能走**（搜图有免密钥来源，补料靠模型自带工具），通不通取决于容器出公网，属部署事实而非能力缺失；且一楼服务器尚未实测，拿"开发机连不通"当禁用依据不成立。等真机验过再说。

### 决策 5：加一条机器检查，防止以后偷偷漏放

在 `tests/contract/engine_param_wiring_test.py` 内追加检查，判据两半，缺一即红：

1. 契约里凡是 `x-unavailable` / `x-unavailable-values` 标了的项，后端拒绝逻辑必须覆盖到——标了却没拦，等于假控件换个形式回来。
2. 反过来，凡后端拦了的项，契约必须有标记——只在后端拦、界面照常可选，用户会被接口错误莫名其妙地挡住。

并配"必须不红"的破坏用例（照本仓惯例：判据只有能被证伪才算能看守）。

### 决策 6（待批示）：解除标记的条件

暂定：**真实跑通一次再解除**，不凭"依赖装上了"就放开。具体两件事，各自独立：

- 旁白音频：后端镜像装上 ffmpeg 系列工具 → 重建镜像 → 起服务、界面开启该项、走"上传素材→生成草稿→生成演示文件"的真实路径 → 拿到的 PPTX 里确实带音频且能自动翻页。
- AI 生图：配好 `IMAGE_BACKEND` 与对应密钥 → 同上真实路径 → 产物里确实有生成的图，且不是占位符。

任一项验通，只删它自己的标记，另一项保持置灰。

## 后果

- 契约多两个字段，前端、后端、测试三处各读它一次；字段只表达"现在不能用 + 原因"，不承担其他语义。
- 历史上已经带 `ai` 提交过的任务，重跑会被拒绝并提示改选。这是有意选择：让失败发生在提交那一刻，而不是发生在产物交付之后。
- `deploy/.env.example` 仍缺这些配置项的样例——那属本 ADR 之外的第二步（补齐模板并写明"不配会怎样"），本批不做，避免和禁用动作混在一批里改不清白。
