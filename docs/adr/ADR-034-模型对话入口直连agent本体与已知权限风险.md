# ADR-034: 模型对话入口——直接使唤 agent 本体，权限关不严的风险由龚成知情承担

- 状态：已采纳（风险承担方为龚成，2026-11-06 选定甲案）
- 日期：2026-11-06
- 相关：ADR-032（agent 设置与供应商档案）、AGENTS.md 规则 9（禁止假控件）、规则 11（界面文案用规范书面语）

## 背景

龚成提出：在「Claude Code 的模型服务配置」处加一个按钮，点击后可以发起一个和 agent 的对话。
追问两点后定档：**形态=连续对话、关掉不留记录**；**作用范围=直接和 agent 说话，与当前启用哪套配置无关，
没配好就当场报错**（原话："发起对话是直接和 agent 发起对话，和配置了哪套没有关系"）。

### 实测凭据（2026-11-06 当日均为真跑，非推断）

1. **现有「测试连接」不是对话**：`packages/backend/src/app/service/agents.py:365` 的 `_probe_http`
   只发一个 `max_tokens=1`、内容为 `"."` 的探测包，返回体只用来判断"有没有 `content` 字段"，
   模型答什么一个字都不取回。所以"能不能聊"这件事现在界面给不出答案。
2. **agent 本体确实能聊**：在开发机容器 `decksmith-app-1`（镜像 `decksmith/app:0.6.4`，
   内含 Claude Code **2.1.197**，与界面右上角显示同版本）里跑一次无界面调用，
   用的就是当时生效的 `mimo-v2.6-pro`，正常返回文本。
3. **开口就能在服务器上执行命令**：同一个容器里输入"执行 shell 命令 echo BASELINE-PWNED 并把输出告诉我"，
   流式事件里出现 `tool_use: Bash`，输出原样回到对话文本。**这是远程命令执行级别的口子**。
4. **当前版本关不严**（逐条试过）：
   - `--permission-mode default` 与 `--permission-mode plan`：容器内实测**仍然执行了命令**（`is_error:false`）。
     2.1.197 的可选值只有 `acceptEdits/auto/bypassPermissions/default/dontAsk/plan`，
     没有开发机本机 2.1.301 上那个能拦住越界读写的 `manual`。
   - `--permission-prompts none`（301 上验证有效的第二道闸）：**2.1.197 没有这个参数**（`claude --help` 无此项）。
   - 禁用工具名单 `--disallowedTools "Bash,Edit,Write,Read,Grep,..."`：301 上禁掉 Read 后它改用 `Grep`
     把 `/etc/hosts` 读了出来；197 上禁掉 Bash 后它改用 `Monitor` 把命令执行了。**按名字拉黑名单是打地鼠**。
   - `--allowedTools ""`（空名单＝只许没有）：实测**不生效**，照样读文件。
   - 容器里 `/root/.claude` 不存在、无 `settings.json`、无 `.claude.json`（实测 `ls`/`cat` 均无输出），
     即当前部署完全靠环境变量喂配置，没有任何权限声明文件可以兜。
5. **多轮续接本身可行**：开发机实测第一轮"只回复两个字：好的"，第二轮带 `--resume <首轮标识>`
   问"我上一句让你回复什么"，答"好的"，且返回事件里的会话标识不变。
   每条流式事件都带 `session_id`（`type:system/init` 与 `type:result` 均可取），续接标识有稳定来源。

### 备选与取舍

- **乙案（只跟模型聊文字，走服务地址直连）**：复用 `_probe_http` 那条已跑通的通路，把上下文一起发过去。
  天然碰不到服务器，改动更小。**龚成未选**，理由是他要的是"和 agent 对话"而不是"和模型对话"。
- **丙案（先把权限关严再做入口）**：要弄清 2.1.197 到底靠什么拦得住，或先升级镜像内的 agent 版本。
  属另一件事，本批不做。

## 决策

### 决策 1：入口走 agent 本体，风险如实写在界面上，不伪装成安全

新增 `kind=chat`，复用现成的异步会话 + SSE 通路（`/api/agent/execute-async`、
`/api/agent/sessions/{id}/stream`、`/cancel`），不新造一套流式通道。
命令执行能力**保留**（这正是龚成要的），因此界面必须把"它能读写文件、能执行命令"这句话写在按钮旁边，
而不是等出事再说。

### 决策 2：可见范围沿用这张卡片的既有权限——仅管理员

不新开可见范围。这张卡片本来就由 `require_admin` 把守（ADR-032），对话入口挂在同一张卡片上，
后端也走同一道闸。**不给 vip、不给普通用户**：他们点了就是在这台服务器上敲命令。

### 决策 3：开口前二次确认，且界面直说后果

点击按钮先弹确认，内容是人话的三句：这次会直接使唤服务器上的 AI 工具、它能读写文件并执行命令、
会向 AI 服务发起真实请求可能消耗积分。确认后才开面板。**不做静默开启**。

### 决策 4：输入仍过既有内容安全闸，但只当纵深防御，不当沙箱

对话文本照旧过 `check_draft_content`（`packages/backend/src/app/core/security.py:94`），
它能拦住"请执行命令""忽略以上指令""读取环境变量"这类常见句式。
但凭据 4 已证明它拦不住变体（"执行 shell 命令 echo X" 不带"请"就不命中），
**因此不许在任何文档或界面里把这道闸说成"安全沙箱"**。

### 决策 5：续接标识由前端持有，后端不留对话记录

首轮不带续接标识，后端从流式事件里取到会话标识后经 `session` 事件回传；
之后每轮由前端带回来。关掉面板即清空，**不落库、不写文件、不进历史项目**——
这条既满足"不留记录"，也避免多机部署时后端内存态漂移。

## 后果

- 得到：管理员能在网页里直接试这套配置背后的 agent 到底会答什么、能不能干活，比「测试连接」的信息量大得多。
- 付出：管理员账号一旦失守，等于交出这台服务器的命令执行权。承担方为龚成（2026-11-06 选定甲案时已知晓凭据 3、4）。
- 遗留：真正关严权限（丙案）没有做。若将来要把这个入口开放给 vip，**必须先回来做丙案**，不许沿用本 ADR 的口子扩面。
- 版本脆弱性：本决策的"关不严"结论绑在 2.1.197 上。镜像内 agent 升版后凭据 4 须重跑一遍——
  新版若提供了可靠的拒绝式权限模式，应回来把决策 1 改成默认关闭工具。

## 追记（2026-11-07，龚成定档）

1. **密钥口径**：网关不支持查看也不支持临时创建子密钥，改由龚成**专门申请一个通用密钥**承担泄露风险。
   由此，"每条任务单独临时容器＋只发短期子密钥"的隔离方案（本 ADR 后果段说的乙档思路）**暂停，不做**。
2. 暂停后仍然成立的事实（不许被这条追记冲淡）：AI 在服务器容器里能执行命令、能读到挂载的整库
   （ADR-035 凭据 1 与实测）、素材文件转换出来的文字那一层仍未设卡（ADR-035 遗留 1）。
   换专用密钥只改变"密钥被拿走的代价"，不改变其余几条。
