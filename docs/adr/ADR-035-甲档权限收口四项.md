# ADR-035: 甲档收口——生成内容过检查、上传按身份隔离、废弃拟题接口下线、取消认主人

- 状态：已采纳（龚成 2026-11-07 批示"先按甲档做"）
- 日期：2026-11-07
- 相关：ADR-034（模型对话入口与已知权限风险）、ADR-019 决策 7（per-identity 粗闸）、AGENTS.md 规则 9（禁止假控件）

## 背景

ADR-034 把"AI 能在服务器上执行命令"这件事摆到台面上之后，做了一轮只读权限体检，实测出五条与"界面说的口径"不一致的地方：

1. **生成任务完全不过内容检查**。`check_draft_content` 全项目只有 4 个调用处，全在 agent 入口
   （`routes.py:184`、`routes.py:496`、`routes.py:587`、`agent.py:189/250`）；
   提交生成（`service/jobs.py:193 submit`）从校验到落库一次都没查。而生成引擎跑 AI 时带
   `--dangerously-skip-permissions`（`packages/engine/impl/ppt_master/engine.py:613`、
   `ppt_master_v6/engine.py:612`、`guizang_ppt/engine.py:424`），意思是"不用问，直接干"。
2. **提交生成不要求登录**。`POST /api/decks`（`routes.py:262`）用 `get_identity`，
   未登录的试用身份照样能提交，只有一条未完成任务数上限拦着（`service/jobs.py:208`）。
   这条**是产品设定**（试用入口），本 ADR 不动它，只把"素材进 AI 之前先查一遍"补上。
3. **上传区无人认领**。`POST /api/upload`（`routes.py:118`）不看身份，谁都能往
   `JOBS_ROOT/uploads/<随机段>/` 里塞 50MB；引用侧只验"路径在 uploads 里面"
   （`routes.py:167`、`agent.py:49`），**不验是不是你自己的**。
4. **已废弃的拟题接口还挂着**。`POST /api/engines/suggest-title`（`routes.py:139`）
   无身份校验，且能读上传区任意文件并调 AI。实测前端与脚本、部署目录都没有调用方，
   只有契约里还留着这条路径（`openapi.yaml:1127`）。
5. **取消别人的任务不查归属**。`POST /api/agent/sessions/{id}/cancel`（`agent.py:340`）
   无身份校验；会话对象里也没记过是谁发起的。

## 决策

### 决策 1：素材进 AI 之前先过检查，落在提交处，报错口径与 agent 入口同一句

在 `service/jobs.submit` 里检查三样：`content` 全文、`sources` 里 `type=text` 的值全文、
`type=file_path` 指向上传区且能按文本读出来的文件全文。
不通过就当场 400，句子沿用 agent 入口那条「XX疑似包含YY，请修改后重新提交」，
**不新造一套说法**（规则 11：同一概念多处叫法要同批）。

**这一层的边界如实写明**：docx/pdf 这类文件是由引擎在任务里转成文字的
（`ppt_master/engine.py:384 _run_source_to_md`），提交时手上只有原始字节，
所以**转换出来的文字这一层还没守住**。要守住必须在每个引擎拼提示词处设卡，
那是另一批活，见「遗留」第 1 条。本决策不许被叙述成"生成路径已经全面检查"。

### 决策 2：上传按身份隔离，试用照样能用

上传目录改成按身份分一段：`JOBS_ROOT/uploads/<身份段>/<上传号>/<文件名>`。
身份段由 `ownership.space_key(identity)` 一处算出：登录用户 `u_<用户号>`、试用 `v_<访客令牌>`。
引用侧的校验从"在 uploads 里面"升级为"在你自己那一段里面"，
共用同一个函数，不在三个调用点各写一套（防止口径漂移）。

`/api/upload` 从此要求有身份。**这不切断试用**：访客令牌在进入页面时由
`GET /api/auth/me` 顺带下发（`core/auth.py:97`、`AuthProvider.tsx:34` 开机即调），
所以真从界面来的请求一定带令牌；不带令牌的请求说明不是从界面来的。
无身份返回 401，句子沿用既有口径「请先登录后再上传」——试用用户也走这句，
因为他手上一定有令牌，不会出现"试用被拦在门外"。

历史遗留：改目录布局后，**旧的扁平上传区里的文件不再可引用**。素材是一次性用的
（上传→提交→生成完），不做搬迁；这条写在这里是为了将来有人翻到旧目录时知道为什么。

### 决策 3：废弃的拟题接口下线，契约同步删除

删除 `POST /api/engines/suggest-title` 的实现与契约路径。
拟题能力的唯一入口是 `POST /api/agent/execute`（kind=suggest_title），
它带身份、带内容检查。`SuggestTitleRequest`/`SuggestTitleResult` 两个数据结构
只被这条路径引用，一并删除，不留"契约里还在、代码里已没有"的孤儿。

### 决策 4：取消只认主人，管理员例外；不符按"找不到"回

会话对象创建时记下发起者的 `space_key`。取消时比对：
不是本人且不是管理员 → 404「找不到这次处理记录，请重新发起」——
沿用项目里既有的"不泄露存在性"口径（`_ensure_project`、`submit_revision` 都是这样），
不新造"无权操作"这种会告诉对方"确实存在"的说法。

## 后果

- 得到：粘贴文本与文本类素材在进 AI 前被检查；上传区不再是公共投递口；少一个无身份的废弃口子；
  别人的任务不再能被任意取消。
- 付出：提交生成多一次文件读取与正则匹配（文本类素材按全文读，几 MB 量级在几十毫秒内）；
  旧上传区文件失效。
- 没解决：见遗留。本 ADR 是甲档，不是把 ADR-034 的洞补上——
  **AI 在服务器上能执行命令这件事仍然没关**，那是乙档（单独临时容器跑）的活。

## 遗留（到期不许改口，逐条给判据）

1. **docx/pdf 转换出来的文字无人检查**。判据：在引擎拼提示词处设一道共用检查，
   且加一条看守——凡 `packages/engine` 里出现带 `claude_bin` 的子进程启动点，
   同一个函数内必须调用这道检查，漏一处报红。做这条之前，不许说"生成路径已全面检查"。
2. **`GET /api/agent/sessions/{id}` 与 `GET .../stream` 仍不查身份**。
   会话号是随机值，猜不到，所以先不判红；但归属信息已经记在会话上，
   下一步把这两个读接口纳入同一比对。
3. **`/api/decks` 允许未登录试用提交**，属产品设定。若将来要收紧，
   必须同时改试用文案与配额口径，不许只改后端把界面说过的话作废。
