# 约束条件

## 描述
系统设计和运行时必须遵守的限制条件。

---

## 安全约束

### AI 调用安全

#### 问题
- 正式跑生成时会放开 AI 的权限（让它不打断、自动执行），这时如果内容里藏着恶意指令（提示词注入），就可能被它照做
- 用户上传的草稿里就可能带这种注入
- 直接放开权限去跑，有安全风险

#### 解决方案：先检查、后执行，分两步

- **第一步 安全检查——不放开权限**：先让 AI 只做"这段内容安不安全、有没有注入"的判断。因为没有放开权限，即便内容有猫腻，它也会停下来问人、不会擅自执行。只有它判定"安全"，才进下一步。
- **第二步 正式生成——放开权限**：内容已确认安全，才放开权限让它自动调技能出片。

#### 为什么第一步不会被注入带偏
- 这一步不放开权限，AI 遇到危险动作会暂停、交回人来定
- 用户能看到它在做什么、决定让不让
- 只有拿到"安全"的结论才继续

## 数据约束

### 草稿版本号
- 格式：年月日时分秒（如 20260907143025）
- 同一草稿同一秒内只能保存一次（防止版本冲突）

### 草稿标识
- 每次文件生成草稿时创建新标识
- 编辑保存时标识不变

### 文件名称
- 演示文件默认名称：项目名称_**文件生成时间戳**（年月日时分秒，取生成时刻而非草稿版本号——同一草稿不同时间重复出片时草稿版本号不变会撞名，生成时间戳保证每个文件不同名）
- 子演示文件默认名称：项目名称_保存时刻时间戳（同规则）；父子/分叉谱系靠预览与下载的缩进树体现，不塞进文件名

## 业务约束

### 任务与输出的关系
- 一个草稿引擎任务生成一个草稿
- 一个输出引擎任务生成一个演示文件
- 一个修改任务生成一个子演示文件
- 一个项目可以有多个任务

### 修改链与产物隔离
- 子演示文件汇成一棵以演示文件为根的**版本树**，可分叉：任一版本（原始文件或某个子文件）都能当修改起点
- **每次修改都有一份独立的逐页设计稿和成品，互不混放**：进编辑前先把"要改的那个版本"的逐页设计稿复制一份当工作稿，所有改动只落在复制品上，**绝不回头改原版本**（保证每一版都能回看、原文件和各分支的预览不串）
- **保存 = 发起一次修改任务、在背后重新出成品**，出成功了才留下这个子文件；没出完或失败就不留（下载树里不会出现半成品）
- 同一秒只存一个：同一项目里同一秒只允许落一个子文件（沿用草稿那套）

### 草稿与版本的关系
- 草稿可以有多个版本
- 历史版本不可变
- 可以还原到任意历史版本

### 任务状态
- 任务状态有六种：排队中、进行中、已完成、失败、超时、已取消（含义见 `states/01-任务状态`；旧稿只写了四种、漏了排队中和已取消，已补齐）
- 后四种是结束态，一旦到了就不再变
- 判"任务还在不在推进"，要认它是不是还在"排队中/进行中"这两种没结束的状态里；别用"只要不是进行中就算结束"，那会把排队中的任务误判成已结束

## 技术约束

### 引擎可插拔
- 新引擎只需实现统一接口
- 引擎内部可调用 Agent 能力层
- Agent CLI 保持原生接口，不封装

### 参数结构
- 草稿引擎参数固定：文件列表 + 提示词
- 输出引擎参数动态：每个引擎不同，前端根据参数模式渲染

### 进度获取
- 状态明细通过轮询获取
- 需要读取 Agent 的输出流或日志文件

### 逐页预览

诚实性（只说确定的事）：
- 引擎一页页边写边出，总共几页事先不知道（目标页数只是软约束），而且每页要么整页落好、要么还没有，不存在"半张页"
- 所以预览只讲已确定的事实：只列已经完成的页；不猜总页数、不放"待生成"的空格、不做进度条分母
- "正在生成"只在末尾放一格，表示"下一页正在出"，不假装知道后面还有几页
- 顶部只说"已生成 N 页"（不带 /总数）；目标页数顶多弱提示，绝不参与布局

哪张算一页、怎么排：
- 只有名字符合"页码开头 + 下划线 + 其余"这类命名的文件才算页，临时文件、非页产物一律不算
- 按页码开头的数字大小排序（不是按字符串排，免得第 10 页排到第 2 页前面），去重；页的顺序就是这个排出来的序，不靠文件改动时间猜
- "有哪几页、共几页"只认这一套数法当唯一依据；进度里的"已生成几页、当前第几页"也从这里派生，不允许另跑一套按文件时间的计数（免得两套口径差一页）

产物目录的锁定：
- 第一次找到这个任务的产物目录后就记住它，之后固定读这一处，不再每轮靠时间猜目录
- 这样能根治并发任务、历史遗留目录之间互相串页；实在找不到才退回临时探测

安全（读文件的路由）：
- 读页、或读页里引用到的资源，都挂在引擎声明的那个产物根目录下（不是单个文件），这样页里引用的图片等能一起正确显示
- 请求的路径解析之后必须还落在这个根目录里，越界的一律拒绝（防有人用"上一层/穿越"之类的路径读到别处）
- 只放行白名单里支持的图片、矢量图类型

能力接入（全局、跟具体是哪个引擎无关）：
- "能不能一页页预览"看引擎自己声明会不会逐页报产物，系统不按引擎名字硬判
- 会就自动接入；不会就返回空、界面退回普通下载或新标签打开
- 框架对具体是哪个引擎无感；页怎么出图也跟引擎无关（现在 pptmaster 出的是矢量图页，不引额外的图片渲染依赖）
- "能不能进修改工作台"同理，看引擎有没有自报"能逐页改"这个本事，不看引擎名字；现在 pptmaster 那类（旧版和 v6）有、HTML 引擎没有，所以只有前者的产物露出"修改"入口
- 每个子文件都有自己独立的一份产物，预览复用同一套能力（查它自己那次修改任务即可），不另开通路；以后要放开新的可预览文件类型前，先重新评估这张白名单

## 性能约束

### 内容限制
- 草稿内容传递给 Claude 时，最多15000字符

### 超时控制
- 任务需要设置最大执行时间
- 超时后任务状态变为 timeout

## 约束汇总

| 类别 | 约束内容 |
|------|---------|
| 安全 | 两阶段调用：检查不跳过权限，执行跳过权限 |
| 数据 | 版本号格式、标识唯一性、文件命名（演示文件/子文件均带生成/保存时间戳） |
| 业务 | 任务与输出关系（含修改任务→子文件）、草稿版本关系、修改链与产物隔离、状态规则（六种状态） |
| 技术 | 引擎可插拔、参数结构、进度获取、逐页预览（只说确定的事、读文件防越界、按引擎自报本事接入，含"能逐页改"的修改入口门控） |
| 性能 | 内容限制、超时控制 |
