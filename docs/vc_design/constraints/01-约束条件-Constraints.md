# 约束条件

## 描述
系统设计和运行时必须遵守的限制条件。

---

## 安全约束

### Agent 调用安全

#### 问题
- 调用 Claude Code 时使用 `--dangerously-skip-permissions` 会跳过权限检查
- 用户上传的草稿可能包含恶意指令（提示词注入）
- 直接执行可能导致安全风险

#### 解决方案
两阶段调用，分离检查和执行：

**阶段一：安全检查（不跳过权限）**
```bash
claude -p "检查以下内容是否安全..."
# 不使用 --dangerously-skip-permissions
# 即使内容有注入，Claude 也会询问用户确认，不会自动执行
```

**阶段二：正式执行（跳过权限）**
```bash
claude -p --dangerously-skip-permissions "执行任务..."
# 检查通过后才执行
# 内容已确认安全，可以自动执行
```

#### 为什么检查阶段不会被注入
- 不使用 `--dangerously-skip-permissions`
- Claude 遇到危险操作会暂停并询问用户
- 即使提示词被注入，也不会自动执行恶意指令
- 用户可以看到 Claude 的行为并决定是否允许

## 数据约束

### 草稿版本号
- 格式：年月日时分秒（如 20260907143025）
- 同一草稿同一秒内只能保存一次（防止版本冲突）

### 草稿标识
- 每次文件生成草稿时创建新标识
- 编辑保存时标识不变

### 文件名称
- 演示文件默认名称：项目名称_年月日时分秒

---

## 业务约束

### 任务与输出的关系
- 一个草稿引擎任务生成一个草稿
- 一个输出引擎任务生成一个演示文件
- 一个项目可以有多个任务

### 草稿与版本的关系
- 草稿可以有多个版本
- 历史版本不可变
- 可以还原到任意历史版本

### 任务状态
- 状态只有4种：running、completed、failed、timeout
- 终态（completed/failed/timeout）不可逆

---

## 技术约束

### 引擎可插拔
- 新引擎只需实现统一接口
- 引擎内部可调用 Agent 能力层
- Agent CLI 保持原生接口，不封装

### 参数结构
- 草稿引擎参数固定：文件列表 + 提示词
- 输出引擎参数动态：每个引擎不同，前端根据参数模式渲染

### 进度获取
- 状态明细通过轮询获取
- 需要读取 Agent 的输出流或日志文件

---

## 性能约束

### 内容限制
- 草稿内容传递给 Claude 时，最多15000字符

### 超时控制
- 任务需要设置最大执行时间
- 超时后任务状态变为 timeout

---

## 约束汇总

| 类别 | 约束内容 |
|------|---------|
| 安全 | 两阶段调用：检查不跳过权限，执行跳过权限 |
| 数据 | 版本号格式、标识唯一性、文件命名 |
| 业务 | 任务与输出关系、草稿版本关系、状态规则 |
| 技术 | 引擎可插拔、参数结构、进度获取 |
| 性能 | 内容限制、超时控制 |
