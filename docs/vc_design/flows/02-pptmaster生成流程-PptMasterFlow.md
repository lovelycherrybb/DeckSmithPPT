# pptmaster 生成流程

## 说明
选 pptmaster 引擎生成 PPT 时，系统内部是怎么走的。

---

## 完整流程

```
用户选好草稿版本 + pptmaster 引擎 + 参数
    ↓
系统取草稿内容
    ↓
【先过安全检查】（这一步不放开权限）
    ↓
安全吗？
    ├── 不安全 → 返回原因，让用户改
    ↓ 安全
【正式生成】（这一步才放开权限，按参数拼提示词）
    ↓
调用 pptmaster 技能生成 PPTX
    ↓
任务标记为已完成
    ↓
前端显示结果
```

---

## 为什么要先检查、后执行

- 第一步"安全检查"叫 AI 时**不放开权限**：它照实判断草稿里有没有提示词注入之类的风险；万一有问题会停下来问，不擅自执行。只有判"安全"才进下一步。
- 第二步"正式生成"才**放开权限自动跑**：内容已确认安全，放心让它直接调 pptmaster 技能出片。
- 一句话：先谨慎问一遍，确认没问题再自动跑。

---

## 逐页预览（生成时页面墙怎么长）

生成过程中，引擎每完成一页，前端「任务详情」里的页面墙就如实多出一格；不去猜总共有几页（只说确定的事，见 constraints 逐页预览）。

```
任务在跑
    ↓ 前端按需刷新：只在"页数变了"或"阶段变了"时重新取一次
拿到：已完成的几页 + 当前状态 + 进行到哪一步
    ↓ 渲染
[页1][页2]…[页N] 后面再跟一格，含义看当前阶段
    ├─ 还在生成 → 转圈格"正在出下一页"
    └─ 正在导出 → "正在导出成品"格（不谎报又多了一页）
    ↓ 每完成一页就多一格，末尾那格顺延
任务完成
    ↓ 末尾格消失，整排就是最终这套页；每格能点开、左右翻页放大
```

- "已生成几页"和页面墙都来自引擎逐页报的同一份数，天然对齐。
- 成品出来后照样用这个能力：按这个演示文件当初那次生成任务，就能一页页看成品、也能下载。
- 不支持逐页产物的引擎（单文件网页、草稿那类），这一整套就跳过，界面维持原来的下载 / 新标签打开。

## 参数说明

### 用户能选的
| 参数 | 说明 |
|------|------|
| 视觉风格 | 十几种风格里挑 |
| 叙事模式 | 讲故事的骨架（金字塔/叙事/教学/展示/简报等） |
| 画布尺寸 | 输出的比例和大小 |
| 演讲备注 | 要不要带讲稿备注 |
| 动画 | 动画策略 |

### 系统替用户拼进去的
| 项 | 说明 |
|------|------|
| 标题 | 演示文稿标题 |
| 内容 | 草稿正文 |
| 内容风格 | 写作的语气与取向 |

> 确切的参数名和取值以契约 `docs/contracts/engine.schema.json` 为准，这里只讲人话。

---

## 与其他引擎的区别

| 引擎 | 大致怎么跑 |
|------|---------|
| pptmaster | 用 AI 跑 pptmaster 技能，出 PPTX |
| guizang 网页 | 用 AI 跑 guizang 技能，出单文件网页 PPT |
| 其他 | 待定义 |
