# 登录与试用流程

本文件描述身份相关的流程：未登录试用、登录、登出、改密、访客并入，以及管理员对用户的操作。权限判定规则本身见 `constraints/02-权限与角色`，这里只走时序。

---

## 不登录先试用

**场景**：用户刚打开产品，不想注册/登录，先试试能不能用

**怎么做**：
1. 首页点「开始使用」，直接进入工作台
2. 系统给这个浏览器建一个访客会话（cookie 承载访客令牌），身份等同普通用户
3. 上传素材 → 转草稿 → 选引擎 → 生成，全程可用；引擎参数区只读禁用
4. 此期间产生的项目挂在访客令牌下，只有这台浏览器看得到
5. 点「历史项目 / 设置 / 用户管理」这些菜单 → 跳登录页（试用只放开工作台）

---

## 试用后登录，把项目认领过来

**场景**：试用做了几个项目，觉得好用，登录正式账号

**怎么做**：
1. 首页点「登录」，输入用户名 + 密码
2. 校验通过 → 服务端建登录会话、下发 httpOnly Cookie，右上角出现头像
3. 系统把刚才访客令牌下的项目，重新归属到这个真实用户名下
4. 试用成果不丢，历史项目里立刻能看到；此后按该账号的角色生效

> 如果登录前没试用（访客令牌下无项目），这一步认领为空，直接进正常态。
>
> 从未被认领的访客项目（用户试用后一直没登录就走了）不会凭空消失：它保持「未认领（访客）」状态，普通/高级用户看不到，但**管理员在全部项目里能看到**这类未认领试用项目（作为全局监督）。

---

## 登录 / 登出

**场景**：常规进出

**怎么做**：
1. 登录：用户名 + 密码 → 成功建会话；账号被禁用则拒绝登录并提示
2. 点头像 → 「退出登录」→ 服务端销毁会话、清 Cookie → 回到首页
3. 退出后回到未登录态；此前真实用户名下的项目不再可见（要重新登录才看得到），与访客试用互不串

---

## 用户改自己的密码

**场景**：初始密码是 234567，用户想换成自己的

**怎么做**：
1. 点右上角头像 → 「修改密码」
2. 输入旧密码 + 新密码 → 保存
3. 改密不影响当前会话；下次用新密码登录

---

## 管理员新增一个用户

**场景**：管理员要给同事开一个账号

**怎么做**：
1. 管理员进「用户管理」菜单（仅管理员可见）
2. 新增用户：填用户名（必填、唯一）、昵称、手机号（选填）、是否 Vip
3. 保存 → 该账号初始密码固定 `234567`，角色按是否 Vip 落 normal/vip
4. 把用户名和初始密码告知对方，对方首次登录后自行改密

---

## 管理员改用户 / 重置密码 / 停用

**场景**：用户忘了密码，或某人离职要停号

**怎么做**：
1. 用户管理列表选中某用户
2. 改信息：昵称、手机号、是否 Vip 可改；**用户名不可改**
3. 忘记密码 → 「重置密码」→ 重置为 `234567`，对方再自行改
4. 停用 → 置为禁用：数据与项目都保留，只是禁止登录；需要时再启用
5. 管理员账号 `manager` 不在可改/可停/可删范围内

---

## 管理员处理未认领的访客项目

**场景**：有人试用后没登录就走了，留下一堆未认领的访客项目；或试用者换了设备登录，自助认领没接上

**怎么做**：
1. 管理员在全部项目列表里看到这些项目，「归属用户」列显示「未认领（访客）」
2. 归位 → 「代为认领」：选一个目标真实用户，把该项目重新归属过去
3. 是垃圾试用 → 「删除」：直接删掉（本期管理员删除只放开未认领访客项目）
4. 普通/高级用户看不到也操作不了别人的、更操作不了访客项目

---

## 越权访问被挡

**场景**：普通用户试图访问别人的项目

**怎么做**：
1. 前端根本不会列出他人项目（列表按归属过滤）
2. 即便直接拿项目 ID 打接口，后端按归属复核 → 拒绝（不泄露该是否存在）
3. 管理员不受此限，可访问全部项目

---

## 一句话总结

| 场景 | 一句话 |
|------|--------|
| 试用 | 不登录进工作台，项目挂访客令牌，仅本机可见 |
| 认领 | 登录后访客项目并入真实用户 |
| 登录/登出 | 用户名+密码建会话；禁用号挡登录；登出销毁会话 |
| 改密 | 头像 → 修改密码，旧+新 |
| 建用户 | 管理员填用户名/昵称/手机号/是否Vip，初始密码 234567 |
| 管用户 | 改信息（用户名除外）、重置密码、启用禁用；manager 不可动 |
| 处理未认领访客项目 | 管理员可查看/删除/代为认领（归位到指定用户） |
| 越权 | 列表按归属过滤 + 后端复核，他人项目访问被拒 |
