# pptmaster 修改流程

## 说明

对能逐页编辑的 pptmaster 产物（旧版和 v6 都算），进抽屉式修改工作台一页一页地改，每保存一次就留下一个子演示文件。改的起点可以是原始演示文件，也可以是任意一个已有子文件，所以各版本汇成一棵可分叉的版本树。本流程接在 `flows/02-pptmaster生成流程` 后面。

这一轮只做这些：

- 只走"逐页改 + 重新出成品"这一条路：可以自己拖拽、微调、改字、改色，也可以一句话让 AI 帮你改同一套逐页内容。
- 不碰"直接改一个已经交付出去的 PPTX"那种另一套上游玩法（那是改外部成品，另说）。
- 保存 = 发起一次修改任务、在背后重新出成品；出成功了这次保存才算成，才有能下载的文件。

---

## 入口与门控

```
演示文件库里的一个文件
    ↓ 看引擎自报"能不能逐页改"这个本事（不看引擎名字硬判）
    ├── 能逐页改的 pptmaster 产物 → 显示「修改」；预览顶部能在 原始文件/各子文件 间切换；下载能选版本
    └── 其他（HTML 之类）          → 不显示「修改」，还是原来的预览、下载
```

---

## 完整流程

```
用户在演示文件库点「修改」（起点可以是原始文件，或任一已有子文件 → 往下分叉）
    ↓
找到"改自哪个版本"当初那份逐页设计稿
    ↓
先原样复制一份出来当工作稿（绝不回头改原版本，尤其别动原始文件那份）
    ↓
打开抽屉式工作台（一边是页面墙，一边是逐页编辑器）
    ↓
用户改：拖拽 / 微调 / 改字改色，或打字让 AI 改
    ↓
用户点「保存」
    ↓
发起一次修改任务（和其它任务一样排队、能看进度、能重试、也记 token）
    ↓（若是打字让 AI 改）AI 先照指令改这份工作稿
在背后把改好的工作稿重新导出成成品文件
    ↓
出成功 → 落一个子演示文件（记下：属于哪个原始文件、改自哪个版本、由这次修改任务产生、它自己那份逐页设计稿和成品）
    ↓
工作台和预览刷新，新子文件出现在切换项与下载树里
```

任何一步没成：这次修改任务算失败或超时，**不留子文件**（不会出现能下载却打不开的半成品），用户可以在工作台里接着改或重试。

---

## 各阶段说明

### 进工作台：先复制，再改

要改的那个版本（原始文件，或某个子文件）当初那份逐页设计稿，现在只用来预览。要改之前先复制一份出来，改的全落在复制品上，原版本一点不动——这样每一版都能回看、能对比。

### 两种改法，最后都走同一条出片

- 手动逐页改：改的是复制出来的那份逐页内容。
- 打字让 AI 改：AI 看的、改完写的也都是这份复制品。两种改法最后都交给同一个"重新出成品"的动作。

### 保存就是在背后重新出片

点保存会发起修改任务并在背后重新导出：要等这次导出跑完，才得到一个能下载的子文件。好处是子文件一定有对应的成品文件；代价是保存不是瞬间完成，也得处理导出可能失败。

### 逐页预览和下载都复用现成的

- 逐页预览：原始文件和每个子文件都能一页页看，用的是同一套逐页预览能力，各自看各自那份。
- 下载：从原来"只下当前这一个文件"扩成下载时弹出一棵**缩进树**——原始文件在最外层、子文件按"改自哪个"往里缩进、分叉的并列；每个节点显示"文件名 + 保存时间、改自哪一版"，选中哪个就下载哪个。缩进树口径见 `objects/08-子演示文件`。

## 与生成流程的区别

| 维度 | 生成流程（flows/02） | 修改流程（本文件） |
|------|--------------------|-------------------|
| 进去的是 | 草稿版本 + 引擎参数 | 一个已有版本 + 改好的逐页内容（或一句指令） |
| 任务类别 | 输出引擎任务 | 修改任务 |
| 上游动作 | 从内容生成成品 | 逐页改 + 重新出成品 |
| 出来的是 | 演示文件 | 子演示文件（挂在"改自哪个版本"下面） |
| 产物存放 | 每个任务各存各的 | 同样每个任务各存各的，互不覆盖 |

> 修改任务在引擎那边具体怎么接上——是新加一个"改+重导出"的本事，还是走已有的提交入口、带上那份工作稿——留到定契约时敲，届时补一篇 ADR。
