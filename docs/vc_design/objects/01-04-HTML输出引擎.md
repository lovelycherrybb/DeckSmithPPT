# HTML 输出引擎（guizang-ppt-skill）

## 描述

基于 guizang-ppt-skill 的 HTML 演示文稿生成引擎，将 Markdown 草稿转化为单文件横向翻页网页 PPT。

## 所属类型

输出引擎（OutputEngine）

## 引擎标识

- **引擎名**：`guizang_ppt`
- **引擎类型**：`output`
- **Skill 来源**：[guizang-ppt-skill](https://github.com/op7418/guizang-ppt-skill)（歸藏创建）

## 两种视觉风格

### 风格 A · 电子杂志 × 电子墨水（默认）

- WebGL 流体 / 等高线 / 色散背景
- 衬线标题（Noto Serif SC + Playfair Display）+ 非衬线正文
- 适合：人文分享、行业观察、商业发布、需要"杂志感"的演讲

### 风格 B · 瑞士国际主义（Swiss Style）

- WebGL 极细网格 + 点阵背景
- 全程无衬线（Inter + Helvetica + Noto Sans SC）+ 极致字号对比
- 高反差功能色：克莱因蓝 / 柠檬黄 / 柠檬绿 / 安全橙
- 适合：科技产品、数据汇报、设计/工程领域分享

## 核心功能

- 横向翻页（键盘 ←→、滚轮、触屏、ESC 总览）
- 演讲者模式（右下角 P 键）：当前页/下一页 16:9 预览、讲稿备注、计时
- 观众屏同步（断线恢复）
- 章节幕封、数据大字报、图片网格等模板
- Motion One 入场动效
- 激光笔 / 圈选标注
- 单文件 HTML，可离线打开

## 输入输出

- **输入**：Markdown 草稿内容（来自草稿引擎）
- **输出**：单文件 HTML 演示文稿（含 CSS/JS，可直接浏览器打开）

## 参数结构

以 `docs/contracts/engine.schema.json` 的 `$defs.guizang_ppt` 为唯一事实来源（`title`、
`pages` 属请求级字段，不在 `engine_params` 内）：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `style` | string | 否 | 视觉风格：`magazine`（默认）或 `swiss` |
| `magazine_theme` | string | 否 | 杂志风主题色，仅 `style=magazine` 生效：`monocle` 墨水经典 / `indigo` 靛蓝瓷 / `forest` 森林墨 / `kraft` 牛皮纸 / `dune` 沙丘 |
| `swiss_theme` | string | 否 | 瑞士风主题色，仅 `style=swiss` 生效：`ikb` 克莱因蓝 / `lemon` 柠檬黄 / `green` 柠檬绿 / `orange` 安全橙 |
| `pages` | integer | 否 | 目标页数（不给则由技能按内容节奏判断；参考 15 分钟≈10 页、30 分钟≈20 页） |

## 适用场景

**合适**：
- 线下分享 / 行业内部讲话 / 私享会
- AI 产品发布 / demo day
- 需要强烈个人风格的演讲
- 一次做完、不用翻页工具的网页版 slides

**不合适**：
- 大段表格数据、图表叠加
- 培训课件（信息密度不够）
- 需要多人协作编辑（静态 HTML）

## 执行方式

与 ppt-master 引擎一致，通过 Claude Code 子进程执行，区别在于产物格式（HTML vs PPTX）。

### 构建 Prompt

```
请使用 guizang-ppt-skill 技能生成 HTML 演示文稿：
- 主题：{title}
- 视觉风格：{style}（magazine 或 swiss）
- 内容来源：{content}
- 要求：输出单文件 HTML，包含横向翻页、演讲者模式等完整功能
```

### 调用命令

```bash
claude -p --dangerously-skip-permissions "{prompt}"
```

### 执行流程

1. 读取草稿内容（Markdown），写入 `<jobs_root>/<job_id>/draft.md` 与 `prompt.md`；
2. 构建 prompt：显式给出**技能绝对路径**（`lib/guizang-ppt-skill`）、风格/主题/篇幅、
   **钉死的唯一产物路径** `<jobs_root>/<job_id>/result.html`，并要求跳过技能内的澄清环节
   （无人值守）、完成后按需用 node 跑技能自带校验脚本自检；
3. 以**任务目录为 cwd** 拉起 `claude`（stream-json 流式，事件蒸馏进 `run.log` 供前端轮询）；
4. agent 依 `SKILL.md` 自行完成版式选择、主题节奏、动效与演讲者备注，写出单文件 HTML；
5. 引擎判定产物（文件存在 + mtime 晚于任务启动 + 体积下限）→ `completed`，否则 `failed`；
   超时由看门狗终止子进程并置 `timeout`。

### 与 ppt_master 引擎的刻意差异

| 维度 | ppt_master | guizang_ppt |
|------|-----------|-------------|
| cwd | `lib/ppt-master`（需向其 `projects/` 写产物） | 任务目录（技能目录属上游只读，禁止写入） |
| 产物定位 | 扫 `exports/*.pptx` 取 mtime 最新 | prompt 内钉死 `result.html`，直接查该路径 |
| 逐页预览 | 有（`svg_output/NN_*.svg`，点亮 `page_preview`） | 无（单文件 HTML，有意不实现 `get_pages`） |

### 技能发现

上游 `guizang-ppt-skill` 只有 `SKILL.md`、没有 `AGENTS.md`，靠 Claude Code 的 skills 目录发现。
因此部署/首次运行时把仓库内 submodule **软链**到 `$CLAUDE_CONFIG_DIR`（默认 `~/.claude`）
`/skills/guizang-ppt-skill`，由 `ensure_skill_installed()` 幂等完成；遇用户自有副本只提示、不覆盖。
prompt 同时携带绝对路径，软链失败仅降级为「按路径读取」，不阻断任务。

## 依赖

- Claude Code CLI（`claude`）已安装且已认证，进程可访问 Anthropic API
- Node.js 20+（技能自带校验脚本 `.mjs`）
- `lib/guizang-ppt-skill` submodule 已 checkout（`git submodule update --init --recursive`）
- 可写的 `DECKSMITH_JOBS_ROOT`（默认 `outputs/jobs`）；技能目录无需可写
