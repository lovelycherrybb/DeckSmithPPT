# 引擎

## 描述
系统中的能力组件，负责将输入转化为输出。

## 属性
- 引擎标识
- 显示名称
- 功能描述
- 引擎类型（草稿引擎/输出引擎）
- 参数模式
- 能力位（引擎自报的额外本事，由引擎自己声明、不看引擎名字；见下"能力位"）

## 引擎分类

### 草稿引擎
- 职责：将用户上传的文件转化为 Markdown 草稿
- 特点：每次生成新草稿，不累加
- 输入：文件（Word、PDF、链接、文本等）
- 输出：新草稿
- 参数固定：文件列表 + 提示词（可选）

### 输出引擎
- 职责：将 Markdown 内容生成最终展示文件
- 特点：支持多种输出格式
- 输入：选定的草稿版本
- 输出：PPT、HTML 等
- 参数动态：每个引擎不同，前端根据参数模式渲染表单

## 能力位

引擎除了"生成产物"这件事，还可以各自声明一些额外的本事：能不能一页页地把进度显示出来、能不能中途喊停、能不能把成品逐页拿来改。这些一律**由引擎自己声明，系统不看引擎叫什么名字来判断**，前后端都照着它声明的本事决定某个操作露不露出来。

- **能逐页看进度**：产物是一页一页的，边生成边能预览。
- **能中途取消**：正在跑的任务能被真正叫停；不能叫停的引擎，取消请求会被拒（而不是假装已停、背后还在跑还在烧额度）。
- **能逐页改**：产物有可以一页一页编辑的逐页设计稿，才谈得上进修改工作台。这一轮里，pptmaster 那类引擎声明了这个本事，所以它们的产物在演示文件库里会露出"修改"入口；HTML 这类没有，就不显示。

加一个新的引擎本事，要三处一起对上（引擎自己声明、系统对外说明、前端据此显示），只补一处就会出现"该有的按钮不出现"。具体字段怎么命名、值取哪些，属契约层，见下一层。

## 关联关系
- 引擎 → 任务：1对多

## 设计考虑
- 引擎内部可调用 Agent 能力层
- 每种引擎类型可有多种实现
- 新引擎只需实现统一接口即可接入
