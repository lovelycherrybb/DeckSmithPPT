# 项目

## 描述

单个演示文件生成项目，是系统的顶层聚合根。用户首次生成草稿时自动创建。自本版本起，项目**必须有一个归属主体**——真实用户，或登录前的未认领访客会话；归属决定谁能看见它。

## 属性

- 项目标识
- 项目名称
- 归属主体（真实用户；或登录试用时挂访客会话、标记为「未认领」，登录后并入真实用户。见下方「归属与可见性」）
- 当前草稿（用户正在编辑的草稿及版本）
- 创建时间、更新时间

## 归属与可见性

- 项目由谁创建（或认领）即归属谁，是数据隔离的基本单位。
- **普通用户 / 高级用户**：只能看到归属自己的项目。
- **管理员**：能看到全部项目，**含尚未被认领的访客试用项目**；在管理员视角下，项目列表**比用户视角多一列「归属用户」**，未认领的访客项目该列显示「未认领（访客）」。用户视角不显示该列（因为全是自己的）。
- 管理员对未认领的访客项目可**查看、删除**，也可**代为认领**——把它重新归属到一个指定的真实用户（用于试用者换设备登录后无法自助认领的情况）。
- 归属与可见性的完整判定见 `constraints/02-权限与角色`；访客并入流程见 `flows/03-登录与试用流程`。

## 关联关系

- 项目 → 用户：多对一（归属；管理员可跨用户查看全部）
- 项目 → 任务：1 对多（任务列表通过 API 返回；任务不单独存归属，靠所属项目推导）

## 生命周期

```
用户（或访客）首次上传文件 → 草稿引擎任务 → 新草稿 → 项目自动创建并记录归属
    ↓
可多次：新的草稿引擎任务 → 更多草稿
    ↓
用户选择草稿版本 → 输出引擎任务 → 演示文件
    ↓
可多次：不同参数/引擎 → 不同演示文件

（访客创建的项目）用户登录 → 访客会话下的项目并入该真实用户名下
```

## 设计考虑

- 项目是顶层聚合根，管理所有相关任务；草稿和演示文件通过任务间接关联到项目。
- 支持持续迭代：新增草稿、生成新版本演示文件。
- 任务不冗余存归属用户，一律通过所属项目推导，避免两处归属打架、也避免改归属时漏改任务。
- 「归属用户」列只在管理员视角出现，是管理员与用户唯一的界面差异点之一（另见用户管理菜单仅管理员可见）。
