# 用户

## 描述

系统的使用者，是权限判定与数据归属的主体。项目归属某个用户（或登录前的未认领访客会话），用户只能看到归属自己的项目；管理员例外，可见全部项目（含尚未被认领的访客试用项目）。

用户分三类角色（单一枚举，互斥）：

- **管理员（manager）**：拥有高级用户的全部功能，外加用户管理；可见所有项目。系统内置唯一账号 `manager`，不可被创建、编辑或删除。
- **高级用户（vip）**：拥有全部生成功能（含引擎参数可调），但无用户管理；仅见自己的项目。
- **普通用户（normal）**：能选择引擎并生成，但**引擎参数对其只读禁用**（可见、不可改，提示「高级用户可调整参数」）；仅见自己的项目。

各角色 × 各能力的完整判定规则统一收敛在 `constraints/02-权限与角色`，本对象不重复列矩阵。

## 属性

- 用户标识（内部主键，不外露为登录凭据）
- 用户名（必填、唯一、登录用；创建后不可改，是身份锚点）
- 昵称（展示用，可改；默认取用户名）
- 手机号（非必填）
- 角色（三值枚举：`manager` / `vip` / `normal`）
- 状态（`启用` / `禁用`；禁用＝保留其数据与项目，但**禁止登录**；由管理员切换，管理员自身账号不可禁用）
- 密码（**仅存哈希，不存明文**；重置后统一为 `234567`，用户可自助改密）
- 创建时间、更新时间

## 关联关系

- 用户 → 项目：1 对多（项目归属该用户；项目可见性由此决定）
- 用户 → 用户偏好：1 对 1（每人一份默认引擎/页数/自动保存等使用习惯，跨设备带回）
- 管理员 → 其他用户：可新增、可改信息（用户名除外）、可重置密码、可启用/禁用；**不可改动任何管理员账号本身，仅能改自己的密码**

## 生命周期

```
（内置）系统初始化 → 建 manager 账号（用户名 manager、默认密码 234567、状态启用）
管理员新增用户（用户名必填、昵称/手机号按必填项、是否Vip→决定 normal/vip）→ 初始密码 234567、状态启用
    ↓
用户登录 → 可自助改密
    ↓
管理员改用户信息（用户名除外）/ 重置密码为 234567 / 禁用 ↔ 启用
```

## 访客身份（未登录试用）

未登录用户可直接进入工作台试用。此时其身份不是本对象的实体用户，而是一类**临时访客身份**：服务端为其建访客会话、以 cookie 承载访客令牌，试用期间产生的项目归属该访客会话。一旦登录，这些项目**并入（重新归属）到登录的真实用户**，试用成果不丢。访客会话本身是登录鉴权机制的一部分，不单列对象，归此说明；时序细节见 `flows/03-登录与试用流程`。

## 设计考虑

- 角色是权限判定的唯一依据；配置界面上的「是否 Vip」开关，本质是在 `normal ↔ vip` 之间切换角色，管理员不参与该开关。
- 用户名不可改（登录凭据锚点），昵称可改——把「身份标识」与「展示名」分开。
- 禁用只挡登录、不删数据：被禁用用户的项目仍归属其名下，管理员仍可见（管理员见全部），解除禁用即恢复访问。
- 密码走哈希存储（如 bcrypt/argon2），任何接口不回显密码；重置为固定 `234567` 是运维便利的取舍，用户应尽快自助改密。
