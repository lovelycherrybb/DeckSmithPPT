# 用户偏好

## 描述

每个登录用户一份的使用习惯设置，对应「设置」菜单里的那块内容。它是跨设备带回的个人偏好，不是权限、也不是某个具体任务的参数。未登录访客没有偏好，走系统级默认。

## 属性

- 归属用户（与用户 1 对 1，一个用户一行）
- 默认输出引擎（取值必须是引擎注册表里的真实输出引擎名）
- 默认页数
- 自动保存草稿（开/关）
- 更新时间

> 字段以「设置」页实际暴露的项为准；新增偏好项时在此登记，避免界面上有、模型里没有。

## 关联关系

- 用户 → 用户偏好：1 对 1（用户删除则偏好随之清理）
- 用户偏好 → 创建向导 / 生成弹窗：作为**初始值**被读取，不强制覆盖用户当次的显式选择

## 生命周期

```
用户进入「设置」→ 加载本人偏好（无则显示系统默认）
    ↓
修改并保存 → 落库（每人一份）
    ↓
下次进入工作台/生成弹窗 → 以该偏好预填默认引擎、默认页数等
```

## 设计考虑

- 偏好只是「默认/初始值」，不改变当次操作：用户在向导里临时改的引擎或页数不回写偏好，除非他显式到设置里保存。
- 默认引擎必须是注册表真实引擎名——现有设置页写死的 `html_output` 之类假选项要一并纠正，否则偏好存了个不存在的引擎。
- 偏好受角色约束叠加：普通用户即便设了默认引擎，进入生成时**引擎参数仍按角色只读禁用**（见 `constraints/02-权限与角色`）；偏好不能成为绕过角色限制的口子。
- 存储建议与 `token_usage` 同一取舍：单列 JSON 文本存一张 `user_settings` 表（一人一行），未来加偏好项不必改表结构；本轮无跨用户聚合/排序偏好值的需求，不拆多列。
