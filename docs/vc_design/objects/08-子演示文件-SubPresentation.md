# 子演示文件

## 描述

演示文件被修改后、用户每次手动保存形成的新版本，叫子演示文件。它是一个通用概念，不分引擎：任何演示文件的修改产物都是子演示文件。多个子演示文件归属于同一个原始演示文件（称为"根"）。

子演示文件可以分叉：既能在原始演示文件上改，也能在任意一个已有子文件上接着改，于是所有版本汇成一棵以演示文件为根的"版本树"，而不是一条从头排到尾的线。

> **本轮范围**：对象本身对所有引擎通用，但"能发起修改、产出子文件"这个入口，当前只对能逐页编辑的 pptmaster 系产物开放——某个产物能不能改，看引擎自己声明的本事，不看它叫什么名字。其他产物这一轮还没有修改入口，但子演示文件这个概念不为它们关闭。

## 属性

- 子文件标识
- 归属演示文件（根，多对一）
- 改自哪个版本（根演示文件，或另一个子文件；留空表示直接改自根）——同一个来源可以长出多个子文件，这就是分叉
- 产生它的修改任务
- 文件名称（默认"项目名称_保存时间戳"；版本之间的父子、分支关系靠预览和下载时的缩进树体现，见下）
- 文件格式（与根一致，PPTX）
- 文件位置（这一次修改自己那份产物里的成品文件）
- 逐页内容（这一次修改自己那份产物里的逐页设计稿，用来预览，也用来再次进入编辑）
- 创建/保存时间

## 关联关系

- 演示文件 → 子演示文件：一对多（演示文件是版本树的根）
- 子演示文件 → 子演示文件：多对一（每个子文件挂一个"改自哪个版本"；同一来源可有多个子文件，即分叉）
- 修改任务 → 子演示文件：一对一
- 子演示文件 → 逐页预览：顺着"产生它的那次修改任务"找到那份产物，再取它的逐页页面

## 版本规则

- **版本树、可分叉**：每个子文件记下自己改自哪个版本；树上任何一个节点都能当新的修改起点，长出更多分支。只往后加，不回头改历史。
- **保存即版本**：在工作台点一次"保存"就是发起一次修改任务，任务成功后落一个新的子文件。
- **同一秒只存一个**：同一个项目里，同一秒只允许留下一个子文件（沿用草稿那套，防止时间戳撞名）。
- **历史不可改**：任何已存的子文件都不能被改写，只能从它上面派生新分支。

## 预览与下载呈现

子文件是一棵可分叉的版本树，预览和下载都用**缩进树**来表达父子、兄弟分支关系，不用平铺列表、也不按序号硬排先后（分叉之后根本没有唯一先后，硬排会误导人）。

- **预览顶部切换**：原始演示文件在最外层，子文件按层级往里缩进；每个节点显示"版本时间 + 改自哪个版本"，点中哪个节点就预览那一版的逐页内容。
- **下载选择**：同一棵缩进树，每个节点显示"文件名 + 保存时间、改自哪一版"，选中哪个就下载哪个版本。
- **分叉看得出**：同一个来源派生出多个子文件时，它们并列摆在同一个父节点下面，谁是谁的分支一眼可辨。
- 这棵树是前端按每个版本"改自哪个"的指向，把扁平的一列版本现场拼出来的；展开、选中这些只是临时的界面状态，不写进数据库。

## 设计考虑

- **和草稿多版本一个路子，只是从"线"升成"树"**：草稿管内容层的版本、子文件管成品层的版本，两者都靠"时间戳当版本号、同一秒只存一个、历史不改、随时可回看"这套心智，用户只需理解一套版本概念。
- **每个版本的产物各存各的（关键）**：每次修改都有一份独立的逐页设计稿和成品。进编辑前，先把"要改的那个版本"的逐页设计稿原样复制一份出来当工作稿，所有修改只动这份复制品，**绝不回头改原版本**——否则原版本被改脏，既没法回看，"原文件 ↔ 各分支"的预览对比也就失真了。
- **不单独存归属**：子文件的可见性顺着"子文件 → 演示文件 → 项目"推出来，沿用"项目是唯一按用户隔离的地方"，不额外记归属。
- **能不能下载，由"保存即在背后重新出成品"兜底**：保存后系统在背后把改好的逐页设计稿重新导出成成品，导成功才留下这个子文件；没导完或导失败就不生成，下载树里也就不会出现半成品。具体见 `flows/04-pptmaster修改流程`。
- **文件名怎么认**：默认和根一样是"项目名称_时间戳"，版本关系不靠往文件名里塞标记、而靠上面那棵缩进树表达；下载每一行再补一句"改自哪一版"。真到下载重名困扰时，再考虑要不要给文件名加来源。
