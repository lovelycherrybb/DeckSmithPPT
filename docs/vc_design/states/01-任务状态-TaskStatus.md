# 任务状态

## 描述

任务从创建到结束会经历的状态。

草稿、输出、修改这三类任务用的是同一套状态；修改任务不新增状态，只是"状态明细"那句话会随它此刻在改页面、还是在重新出成品而变化。

状态分两个视角来描述，别混成一张表：

- **任务态**：给用户和前端看的，反映任务整体走到哪一步。
- **引擎态**：引擎只报告它自己那个进程的真实情况，取值更少。

（机器实际读到的状态取值以契约为准——任务态见 `docs/contracts/openapi.yaml`、引擎态见 `docs/contracts/engine.schema.json`；这里用中文把含义讲清楚。）

## 状态一览（任务态）

| 状态 | 会结束吗 | 什么时候是这个状态 |
|------|--------|------|
| 排队中 | 否 | 已经受理、在队列里等，还没真正开跑 |
| 进行中 | 否 | 引擎进程已经起来、正在干活 |
| 已完成 | 是 | 成功出了产物 |
| 失败 | 是 | 干活过程中出了错 |
| 超时 | 是 | 超过了最长允许时间 |
| 已取消 | 是 | 被撤销（排队时直接摘掉，或进行中叫停） |

## 引擎态（是任务态的一部分）

引擎只会报"进行中、已完成、失败、超时"这几种。"排队中"和"已取消"不在引擎态里——排队和取消是上层调度的决定，引擎那个进程根本不知道有队列这回事。引擎报的值一定是任务报的值的子集。

## 状态怎么流转

```
提交 → 排队中 ──开跑──▶ 进行中 ──▶ 已完成
 │                        ├────────▶ 失败
 │                        ├────────▶ 超时
 └────────撤销────────────┴────────▶ 已取消
```

## 状态转换规则

- 排队中 → 进行中：调度认领、引擎进程起来。
- 排队中 → 已取消：用户撤销。
- 进行中 → 已完成 / 失败 / 超时：看引擎这一趟的结果。
- 进行中 → 已取消：用户撤销，且这个引擎能真正叫停。
- 四种结束状态（已完成、失败、超时、已取消）一旦到了就不再变。

## 怎么判断任务"还在不在推进"（重要）

没结束的两种是"排队中、进行中"；结束的四种是"已完成、失败、超时、已取消"。

判任务是不是还在跑，要认"是不是还在那两种没结束的状态里"或"是不是已经到了结束态"，**别用"只要不是'进行中'就算完"**——在还没有"排队中"之前这两种写法等价，可一旦引入"排队中"就错了：正在排队的任务会被当成已结束，于是提前冒出下载按钮、不再刷新、统计漏算。

## 状态明细

- 描述"当前这一刻引擎正在干什么"，随进度变化，前端靠轮询刷新。
- 只有还没结束（排队中、进行中）时才有意义。
- 状态本身才是给机器判断用的；"状态明细"只是给人看的补充，别拿它当判断依据。

### 示例

**排队中**：排队中，前面还有 2 个任务

**草稿任务**：
```
正在读取文件…
→ 正在理解材料内容…
→ 正在生成草稿…
→ 正在优化格式…
```

**输出任务**：
```
正在解析草稿…
→ 正在应用视觉风格…
→ 正在生成幻灯片…
→ 正在导出成品…
```

**修改任务**（改页面 + 重新出成品；打字让 AI 改和手动改，最后都走同一条出片）：
```
正在按你说的改页面…（只有打字让 AI 改时才有这步）
→ 正在校验页面…
→ 正在重新导出成品…
```

## 排队位次

"前面还有几个"这个数，是读取时现算的：数一下排在你前面、还没被认领的有几个，只在排队中时才给。它只是大概参考、不保证准（两次刷新之间可能有人撤销或被插队认领），不写进数据库，也不参与任何状态判断。

## 撤销

- 只能撤销还没结束的任务。
- 排队中：直接从队列摘掉，不产生任何引擎进程。
- 进行中：请求引擎叫停它的进程。**能不能真停下来，看引擎有没有"能中途叫停"这个本事**（见引擎对象的能力位）——有，才真把进程杀掉；没有，就明确告诉用户这个停不了，**绝不假装"已撤销"、背后进程继续跑继续烧额度**。
- 已经写出来的中间产物和成品文件不删（重跑、审计可能还要用，也是文件保护的一贯做法）。
- 撤销前已经烧掉的 token 如实保留，不抹。

## 重试

- 重试不改原任务，而是拿它的参数另开一个新任务。
- 只有没成功的结束态能重试：失败、超时、已取消。
- 已完成、以及还没结束的（排队中、进行中）都不给重试。
- 新任务是独立的一个，重新从排队中开始排。

## 设计考虑

- **为什么分两个视角**：状态的边界要按"谁能产生它"来划，不按"谁要看它"划。把"排队中""已取消"塞进引擎那一层，会让写新引擎的人误以为自己的进程还得管排队，可引擎根本没有队列。这跟"草稿引擎和输出引擎要分成两类，否则能力会被标错"是同一个判断维度。
- **为什么"排队中"要单独算一个状态**：早先"已经受理、但还没开跑"只能写在给人看的那句明细里，机器判不了——于是"进程重启后没人再管它"和"它正在正常跑"看起来一模一样，只能人工去查。把"排队中"提为一个正经状态后，它卡在队列里太久本身就是一个异常信号。
- **结束态不可逆**：四种结束状态都不再变。
- **重试即新建**：不复活老任务，留全审计链。
