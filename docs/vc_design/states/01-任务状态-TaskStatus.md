# 任务状态

## 描述
任务从创建到完成的生命周期状态。

## 状态定义

| 状态 | 说明 |
|------|------|
| running | 运行中，引擎正在执行 |
| completed | 完成，已成功生成输出 |
| failed | 失败，执行过程中出错 |
| timeout | 超时，未能在规定时间内完成 |

## 状态流转
```
任务创建 → running → completed / failed / timeout
```

## 状态转换规则

| 当前状态 | 可转换状态 | 触发条件 |
|---------|-----------|---------|
| running | completed | 引擎成功生成输出 |
| running | failed | 引擎执行出错 |
| running | timeout | 超过最大执行时间 |
| completed | - | 终态，不可转换 |
| failed | - | 终态，不可转换 |
| timeout | - | 终态，不可转换 |

## 状态明细

### 说明
- 当前状态下引擎正在做什么的描述
- 仅在 running 状态下有意义
- 前端通过轮询获取最新状态

### 示例

**草稿引擎任务**：
```
正在读取文件...
→ 正在理解材料内容...
→ 正在生成 Markdown 草稿...
→ 正在优化格式...
```

**输出引擎任务**：
```
正在解析 Markdown...
→ 正在应用视觉风格...
→ 正在生成幻灯片...
→ 正在导出 PPTX...
```

## 设计考虑
- 状态简化为 4 个：running、completed、failed、timeout
- 状态明细提供实时进度反馈
- 终态不可逆

## 重试机制

### 说明
- 重试（retry）不会改变原任务的终态
- 重试会创建一个新任务，复用原任务的参数
- 原任务保持 failed/timeout 状态，新任务有独立的 job_id
- 新任务从 running 状态开始执行

### 流程
```
原任务（failed/timeout）→ 创建新任务（running）→ 新任务执行 → 新任务完成/失败
```

### 设计原则
- **终态不可逆**：failed/timeout 是终态，不可转换为其他状态
- **重试即新建**：重试操作创建新任务，而非修改原任务状态
- **参数复用**：新任务复用原任务的引擎、参数、草稿等配置
